# 기능 요청은 디테일까지

기능을 해 달라고 하면 "돌아가는 최소"에서 멈추지 않고 아이가 실제로 만지는 완성품으로 만든다. 범위를 넓히는 게 아니라 요청한 기능 안의 완성도다(새 기능이 필요해 보이면 먼저 묻는다). 요청에 적혀 있지 않아도 아래를 챙기고, 못 챙긴 것은 보고에 적는다.

- 겉모습: 회색 맨 블록으로 끝내지 않는다. 재질·색·소품·주인공 메시(파트 폴백 포함)까지 둔다.
- 반응: 누르기·사기·완성마다 소리·트윈·파티클·알림 같은 피드백을 단다(긍정만, 기획서 §12.2).
- 상태: 처음·돈 부족·잠김·가득 참·다시 접속·방문객 시점에서 각각 어떻게 보이고 동작하는지 정한다.
- 기기: PC·모바일 터치·게임패드에서 다 누를 수 있고, 작은 화면에서 글자·버튼이 잘리거나 겹치지 않는다.
- 연결: 저장·리더보드·미션·도감 등 이미 있는 시스템과 이어지는지 확인한다. 수치·문구는 `Config` 에, 기획서도 같은 변경에서 맞춘다.
- 확인: 검사 명령 통과로 끝내지 않는다. Studio Play 로 직접 해 보고 화면을 찍어 본다. 못 했으면 못 했다고 적는다.
