# 💡 얼음! 6학년 (가제) — 로블록스 한국 초등학교 잠입 스텔스

> 작성일: 2026-08-15
> 상태: 기획 확정 (구현 계획서 착수 가능)

## 한 줄 요약

칠판에 분필로 수업 중인 선생님이 뒤돌아보는 0.2초를 읽어내며, 한국 초등학교 1학년 1반부터 6학년 12반까지 72개 교실의 빈자리에 몰래 앉아 졸업장을 따는 3인칭 스텔스 진행형 게임.

## 문제 / 타겟 사용자

**타겟:** 로블록스 8~16세 한국·아시아권 유저 중 *Rainbow Friends / Escape 계열 단판 긴장감* 은 좋아하지만, **자기가 아는 공간이 무대인 게임이 없다**고 느끼는 층.

**문제:** "무궁화꽃이 피었습니다" 룰을 쓰는 로블록스 게임은 이미 많지만 대부분 오징어게임 클론이라 **공간이 무국적**이다. 한국 초등학교라는 배경은 (1) 타겟 유저가 매일 있는 곳이라 학습 비용이 0이고, (2) "수업 중인 교실에 몰래 들어가 앉는다"는 상황 자체에 이미 사회적 긴장감이 있어 규칙 설명 없이도 감정이 전달된다.

**주 사용자 (하나만):** *한 판 1분짜리를 짬짬이 반복하며 "몇 학년까지 갔는지"를 친구에게 자랑하고 싶은 모바일 로블록스 유저.*

## 목표 & 성공 지표

**1차 기준(개인 프로젝트):** "1학년 12반이 재미있게 돌아간다."
아래 완성도 체크리스트가 전부 ✅ 되면 성공으로 판정한다.

| # | 완성 조건 | 검증 방법 |
|---|---|---|
| 1 | 감지 판정이 억울하지 않다 | 본인 20판 중 "이건 랙/버그 때문"이라 느낀 판이 1판 이하 |
| 2 | 한 반 클리어 중앙값이 30~60초 | 서버 로그에 반별 클리어 시간 기록 → 히스토그램 확인 |
| 3 | 1반과 12반의 체감이 다르다 | 1반 실패율 <15%, 12반 실패율 40~60% |
| 4 | 예고 신호가 읽힌다 | 튜토리얼 없이 지인 3명에게 시켜 3반까지 도달 |
| 5 | 12명 공용 서버에서 모바일 30FPS 유지 | Studio 서버 시뮬레이션 12클라 + 실기기 확인 |
| 6 | 재접속하면 진행이 남아있다 | 진행 저장 → 강제 종료 → 재입장 왕복 테스트 |

**참고 지표(강제하지 않음):** D1 잔존율 15%+, 평균 세션 8분+.

## MVP 범위 (포함 / 제외)

### ✅ 포함 — "1학년 하나만 완성한다"

- 운동장 **허브**(축소판) + 현관 + **1층 복도** + 교실 문 12개
- **교실 템플릿 1종** + 레이아웃 프리셋 3종(책상 배열 변주)
- 선생님 AI **상태머신 전체** + 패턴 L1(기본 회전), L2(페이크 턴)
- 학생 더미 NPC 18명(Humanoid 없음)
- **감지 시스템**(시야각 × 움직임 × 엄폐 레이캐스트) — 서버 권위
- 이동 3단계(살금살금/걷기/달리기) + 관성 정지
- 방해물 2종: 삐걱 마룻바닥, 바닥 가방
- 난이도 테이블(1학년 1반→12반 보간)
- 별 토큰 + 업그레이드 3종
- DataStore 이어하기
- HUD(학년/반, 별, 선생님 상태 링), 적발 연출, 클리어 연출
- 사운드 8종(분필, 종, 리놀륨 발소리, 웅성거림, 삐걱, 적발 호통, 클리어, 별 획득)

### ❌ 제외 (2차 이후)

2~6학년 콘텐츠 · 패턴 L3~L5(반사 감시/교실 순회/지명 질문) · 코스메틱 상점과 게임패스 · 글로벌 명예의 전당 · 졸업식 컷씬 · 배지/업적 · 친구 초대 보상 · 다국어

> **핵심 원칙:** 2~6학년은 **코드가 아니라 데이터**다. `DifficultyTable[grade][class]`와 `ObstacleSet` 배열만 채우면 콘텐츠가 늘어나도록 MVP를 짠다. 이게 지켜지지 않으면 솔로 개발로 72반은 절대 못 간다.

## 핵심 사용자 플로우

### A. 첫 입장

```
운동장 스폰(허브)
 → 안내 표지판 "수업 중 · 조용히" (튜토리얼 대체)
 → 현관 신발장에서 실내화 갈아신기 (= 로딩/진입 트리거)
 → 1층 복도 진입
 → "1-1" 반 팻말 문 앞 프롬프트 [E / 화면 버튼: 문 열기]
 → 교실 개인 인스턴스로 전송
```

### B. 교실 한 판 (게임의 심장, 30~60초)

```
1. 교실 뒷문에서 시작. 선생님은 칠판을 보며 분필 소리 사각사각.
2. 화면에 빈자리 1~2개가 은은한 아웃라인으로 표시(첫 3반만).
3. 플레이어가 살금살금/걷기로 책상 사이 통로를 전진.
4. [예고] 분필 소리가 뚝 끊기고 선생님 어깨가 살짝 들썩 (grade별 0.75s~0.15s)
5. [회전] 선생님이 몸을 돌린다 (turnTime 0.45s~0.22s)
6. [감시] watchTime 동안 정면 시야각 안 + 움직임 감지 시 적발
     └ 시야 밖(뒤쪽 사물함/기둥 뒤/책상 밑) 또는 레이캐스트 차단 시 안전
7. [복귀] 다시 칠판으로. 분필 소리 재개 → 이동 재개
8. 빈 의자에 닿는 순간 → 자동 착석 애니메이션 → 즉시 클리어
9. 클리어 연출: 화면 밝아짐 + "1학년 1반 클리어" + ⭐ 획득
10. 자동으로 복도 복귀, 다음 반 문이 강조됨
```

### C. 적발 시

```
선생님 확대 컷(0.8초) + "거기 누구야!" 호통 + 학생들 일제히 뒤돌아봄
 → 화면 페이드
 → 같은 교실 문 앞에서 재시작 (진행도 유지, 연속 클리어 콤보만 리셋)
```

### D. 성장 루프

```
반 클리어 → ⭐1~3 획득 → 복도 벽 "학급 게시판" UI에서 업그레이드 구매
 → 12반 클리어 → 계단 개방 → 다음 학년
 → 6학년 12반 → 졸업장 + 명예의 전당 등재 + 게임 종료 화면
```

## 게임 시스템 상세

### 1. 선생님 상태 머신 (서버 권위)

| 상태 | 지속 | 플레이어 상태 | 클라이언트 표현 |
|---|---|---|---|
| `TEACHING` | teachTime (랜덤 ±20%) | 자유 이동 | 분필 사각사각, 칠판에 글자 누적 |
| `WARNING` | warnTime | 자유 이동 | **분필 소리 정지 + 어깨 들썩 + 팔 내림** |
| `TURNING` | turnTime | 이미 판정 시작 (여기서 뛰면 죽음) | 상체→하체 순 회전 애니메이션 |
| `WATCHING` | watchTime (랜덤 ±25%) | **정지 필수** | 교실 앰비언스 정적, 시계 초침 소리 |
| `RETURNING` | turnTime | 자유 이동 (마지막 0.3초는 유예) | 다시 칠판으로 |
| `FAKE_TURN` | warnTime + 0.3s | 자유 이동 | 어깨만 들썩이고 안 돌아봄 → 플레이어 낚시 |

**페이크 턴 규칙:** `WARNING` 진입 시 `fakeChance` 확률로 `FAKE_TURN`으로 분기. 페이크 직후에는 **연속 페이크 금지**(2연속 낚시는 억울하게 느껴진다).

### 2. 감지 알고리즘 (서버, Heartbeat 1/2 프레임)

판정 순서는 **가벼운 연산부터**: 거리 → 시야각 → 레이캐스트.

```lua
-- WATCHING 또는 TURNING 후반부에만 실행
local toPlayer = (hrp.Position - teacherHead.Position)
local dist = toPlayer.Magnitude
if dist > MAX_SIGHT then return end                    -- 교실 뒤 8m 밖은 사각

-- (1) 시야각
local cosAngle = teacherHead.CFrame.LookVector:Dot(toPlayer.Unit)
if cosAngle < math.cos(math.rad(fovDeg / 2)) then return end   -- 시야 밖 = 안전

-- (2) 엄폐 (사물함·청소함·기둥·책상 밑만 차단, 학생 NPC는 통과)
local hit = workspace:Raycast(teacherHead.Position, toPlayer, coverParams)
if hit and hit.Instance:HasTag("Cover") then return end        -- 가려짐 = 안전

-- (3) 움직임 — ★ 서버가 직접 기록한 위치 델타로만 판정한다
local prev = lastPositions[player]
local moved = prev and (hrp.Position - prev).Magnitude or 0
if moved > MOVE_EPSILON then                            -- 기본 0.05 stud/tick
    Detection:Catch(player, "moved_in_sight")
end
lastPositions[player] = hrp.Position
```

> ⚠️ **`AssemblyLinearVelocity`를 쓰면 안 된다.** 클래식 복제에서 플레이어 캐릭터의 물리 소유권은 클라이언트에 있으므로, 속도 값은 **클라이언트가 보고하는 값**이다. 익스플로이터가 "속도 0"을 보고하면서 자유롭게 이동하면 감지 시스템 전체가 무력화된다.
> 반면 **위치는 실제로 이동해야만 바뀐다.** 서버가 매 틱 `HumanoidRootPart.Position`을 자체 테이블에 기록해 델타를 계산하면 위조할 수 없다. 이 게임의 감지 시스템은 반드시 이 방식이어야 한다.

**억울함 방지 3종 세트 (반드시 구현):**

- `GRACE = 0.20s` — `TURNING` 시작 후 0.2초는 판정 유예 (반응 시간 보장)
- `MOVE_EPSILON = 0.05 stud/tick` (20Hz 기준 약 1 stud/s) — 물리 지터·경사 미끄러짐을 흡수
- 적발 시 서버가 **판정 근거를 클라에 전송** → 디버그 모드에서 "왜 죽었는지" 확인 가능 (밸런싱 필수 도구)

**인증 모델:** 클래식 복제 + 서버 검증. `Workspace.AuthorityMode = Server`(Server Authority)는 이 게임에 이상적이지만 이동 구현과 감속 커브를 통째로 재설계해야 하므로 MVP에서는 쓰지 않는다. 위 위치 델타 판정과 `RequestSit` 거리 검증으로 실질적 치트 위협은 막힌다.

### 3. 이동 시스템

| 모드 | 속도 | 정지까지 | 발소리 반경 | 입력 |
|---|---|---|---|---|
| 살금살금 | 4 st/s | 0.08s | 0 (무음) | Shift 유지 / 모바일 좌하단 버튼 |
| 걷기 | 10 st/s | 0.35s | 6 st | 기본 |
| 달리기 | 17 st/s | 0.75s | 18 st (**선생님 즉시 회전 트리거**) | Ctrl·더블탭 / 모바일 우하단 |

> **이 표가 게임의 전부다.** "빨리 가고 싶다 ↔ 못 멈춘다"의 트레이드오프가 재미의 100%. 정지 시간은 `Humanoid.WalkSpeed`를 0으로 바꾸는 게 아니라, 커스텀 감속 커브(`AssemblyLinearVelocity`를 lerp)로 구현해야 "미끄러져서 죽는" 손맛이 산다.

## 기술 접근

### 서버 구조 — 공용 서버 + 개인 교실 인스턴스

- 서버 최대 **12명**. 운동장·복도는 공유 공간(다른 플레이어가 보인다).
- 교실은 **슬롯 방식**: 서버 시작 시 `Workspace.ClassroomSlots`에 12개 슬롯을 `X = 5000 * slotIndex`로 멀찍이 배치.
- 플레이어가 문에 들어가면 자기 슬롯으로 `CFrame` 이동. **`StreamingEnabled = true`** 덕분에 남의 슬롯은 클라이언트에 스트리밍되지 않는다 → 렌더 부담 사실상 1교실.
- **⚠️ 텔레포트 전에 반드시 `Player:RequestStreamAroundAsync(slotPosition)`을 먼저 호출한다.** 스트리밍 반경 기본값이 1024 stud라, 5000 stud 떨어진 슬롯으로 그냥 순간이동하면 교실이 아직 스트리밍되지 않아 빈 공간에 떨어진다. 이 대기 시간(0.3~1초)을 **"문 여는 연출"로 가린다.** `StreamingIntegrityMode`도 함께 설정할 것.
- 스트리밍 아웃된 인스턴스는 **파괴되는 게 아니라 `Parent = nil`이 된다.** 클라이언트 스크립트가 교실 파트를 참조할 때 `FindFirstChild`는 `nil`을 반환하므로 **타임아웃이 있는 `WaitForChild`**를 쓴다.
- 나가면 슬롯 반납 + 교실 리셋. 슬롯 부족 시(13번째) 대기 없이 재사용 풀에서 회수.

### 학생 NPC — 클라이언트 전용 렌더

학생 18명 × 12슬롯 = 216명(약 1,500파트). **`StreamingEnabled`는 클라이언트 렌더링만 줄이지 서버 부하는 줄이지 않는다** — 학생이 서버에 존재하면 서버 DataModel 메모리와 복제 비용을 그대로 먹는다.

**따라서 학생은 서버에 두지 않는다.**

| 위치 | 무엇이 있나 |
|---|---|
| **서버** | 좌석 파트 18개(교실당)만. `Seat` 태그 + `IsEmpty` 어트리뷰트. 착석 판정과 빈자리 지정만 담당. |
| **클라이언트** | 좌석 위치를 읽어 학생 모델 18개를 로컬 생성. 시각적 존재일 뿐 서버는 모른다. |

- 학생 모델 = **Anchored Model, Humanoid 없음, 파트 7개** (머리/몸통/팔2/다리2 접힌 포즈)
- 앉아있는 정적 포즈. 미세 idle(고개 끄덕임, 연필 움직임)은 `TweenService`로, 역시 클라이언트에서만.
- 서버 인스턴스가 1,512개 → **216개**로 줄어든다.
- 선생님만 서버에 실체가 있고 `Humanoid` + `Animator`를 쓴다 (회전/순회 애니메이션 필요, 감지 판정의 기준점이므로 서버 권위여야 한다).
- 선생님의 교실 순회(5학년)는 **고정 웨이포인트**로 처리한다. `PathfindingService`는 불필요하다 — 경로가 정해져 있고 장애물이 없다.

### 네트워킹 (서버 권위 원칙)

| 방향 | 이벤트 | 내용 |
|---|---|---|
| S→C | `TeacherStateChanged` | `{state, duration, isFake}` — 클라는 연출만 |
| S→C | `Caught` | `{reason, teacherCFrame}` |
| S→C | `ClassCleared` | `{grade, class, stars, timeSec}` |
| C→S | `RequestEnterClassroom` | `{grade, class}` — 서버가 진행도 검증 후 승인 |
| C→S | `RequestSit` | `{seatId}` — 서버가 거리·상태 재검증 |
| C→S | `PurchaseUpgrade` | `{upgradeId}` — 서버가 별 잔액 검증 |

**절대 클라이언트를 믿지 않는다.** 특히 `RequestSit`은 거리 체크 없이 받으면 텔레포트 치트로 72반이 3초에 뚫린다. 서버는 좌석까지의 거리, 해당 좌석이 실제로 빈자리인지, 플레이어가 그 교실에 있는지, 마지막 요청 이후 쿨다운을 모두 검증한다.

**`RemoteEvent`는 어트리뷰트·프로퍼티 복제와 순서가 보장되지 않는다.** 선생님 상태는 반드시 `TeacherStateChanged` **단일 채널**로만 보내고, 페이로드에 `stateVersion`(단조 증가 정수)을 실어 클라이언트가 순서가 뒤바뀐 패킷을 버릴 수 있게 한다. 상태를 어트리뷰트로도 같이 노출하는 이중 채널은 만들지 않는다.

모든 리모트에 **레이트 리밋**을 건다. 다만 레이트 리밋은 서버를 보호할 뿐이므로, 검증은 별도로 전부 해야 한다.

### 데이터 스키마 (ProfileStore)

```lua
DEFAULT_PROFILE = {
    version = 1,
    progress = { grade = 1, class = 1 },
    stars = 0,
    upgrades = { quietShoes = 0, balance = 0, instinct = 0 },
    cosmetics = { owned = {}, equipped = { uniform = "default" } },
    run = {                      -- 명예의 전당용 누적
        totalSeconds = 0,        -- 교실 안에서 보낸 시간만 누적
        graduated = false,
        graduatedAt = nil,
    },
    stats = { attempts = 0, caught = 0, perfectClears = 0 },
}
```

**마이그레이션 필수:** `version` 필드로 스키마 변경 시 업그레이드 함수를 태운다. 안 해두면 2학년 콘텐츠를 추가할 때 기존 유저 데이터가 깨진다.

**⚠️ 저장 시점 — 반 클리어마다 저장하면 안 된다.**
2026년부터 experience별 DataStore 쿼터가 강제되고, 초과하면 에러가 아니라 **throttle**된다. 72반 × 저장이면 쓰기 폭탄이다. 진행 상태는 **세션 테이블(메모리)**에 두고 아래 세 시점에만 쓴다.

| 시점 | 이유 |
|---|---|
| 60초 주기 오토세이브 | 크래시 대비, 최대 손실 1분 |
| 학년 승급 시 | 의미 있는 마일스톤 |
| 퇴장 + `BindToClose` | `PlayerRemoving`만으로는 서버 종료 시 유실된다 |

**세션 락 필수:** 두 서버가 같은 프로필을 동시에 쓰지 않도록 세션 소유권 프로토콜을 둔다. ProfileStore를 쓴다면 `StartSessionAsync` / `OnSessionEnd` / `EndSession`을 문서대로 쓰고, 일반 로딩에 `Steal` 옵션은 쓰지 않는다. Studio 테스트는 `ProfileStore.Mock`으로 실제 키를 건드리지 않는다.
**DataStore2는 deprecated이므로 쓰지 않는다.** 네이티브 `DataStoreService` 또는 ProfileStore를 쓴다.

### 명예의 전당 (2차)

`OrderedDataStore("GraduationTime_v1")`에 `totalSeconds`를 저장 (낮을수록 상위). 운동장 조회대 옆 **명예의 전당 비석**에 Top 50 표시. `MessagingService`로 신규 졸업 시 전 서버 공지.

### 수익화 (2차, 외형 + 편의)

| 상품 | 종류 | 내용 |
|---|---|---|
| 교복·체육복·실내화 세트 | 게임패스 | 외형만, 성능 영향 없음 |
| 가방·명찰·이모티콘 | 개발자 상품 | 외형/감정표현 |
| "이어하기 부스트" | 게임패스 | 접속 시 마지막 교실 문 앞에서 바로 시작 (기본은 복도 입구) |
| VIP 운동장 구역 | 게임패스 | 허브 전용 공간·의자 |

실력 이점(목숨 추가, 예고 연장, 레이더)은 **판매하지 않는다** — 랭킹 공정성이 깨지고 pay-to-win 반발을 부른다.

## 첫 구현 단계 (5개)

> 각 단계는 **끝나면 플레이 가능한 상태**여야 한다. 순서를 지킬 것.

**1단계 — 교실 1개와 감지 시스템만 (2~4일)**
회색 박스 교실 하나, 선생님 파트 하나(회전만), 플레이어. `TeacherAI` 상태머신 + `DetectionService` 완성.
→ **검증:** 시야 안에서 움직이면 죽고, 사물함 뒤에 숨으면 안 죽고, 시야 밖에서는 뛰어도 안 죽는다. 20판 돌려 억울한 죽음 0.

**2단계 — 이동 3단계 손맛 (1~2일)**
`MovementController`의 커스텀 감속 커브. 살금/걷기/달리기와 정지 시간 표를 그대로 구현. 모바일 버튼 포함.
→ **검증:** 달리다가 `WARNING` 신호를 보고 멈추면 **아슬아슬하게 늦어서 죽는다.** 이게 안 되면 게임이 없다.

**3단계 — 교실 템플릿 + 학생 18명 + 착석 (3~5일)**
실제 아트 교실, Humanoid 없는 학생 더미, 빈자리 랜덤 지정, `RequestSit` 서버 검증, 클리어/적발 연출.
→ **검증:** 한 판이 30~60초에 끝난다. 서버 12슬롯 스폰 후 모바일에서 30FPS 유지.

**4단계 — 12반 루프 + 진행 저장 (2~3일)**
복도, 문 12개, `DifficultyTable` 보간, 별/업그레이드 3종, ProfileStore 저장.
→ **검증:** 1반→12반이 이어지고, 강제 종료 후 재입장 시 이어진다. 1반 실패율 <15%, 12반 40~60%.

**5단계 — 운동장 허브 + 폴리시 (3~5일)**
운동장 에셋, 현관 신발장 진입 연출, 사운드 8종, HUD, 조명 세팅.
→ **검증:** 튜토리얼 없이 지인 3명이 3반까지 도달한다.

이후 확장: 2학년 → 반사 감시(L3) → 순회(L4) → 지명 질문(L5) → 코스메틱/게임패스 → 명예의 전당 → 졸업식.

## 리스크 & 오픈 질문

**🟡 리스크 1 — 12슬롯 교실의 성능 (설계로 상당 부분 해소됨)**
학생을 클라이언트 전용 렌더로 돌려 서버 인스턴스를 1,512개 → 216개로 줄였고, `StreamingEnabled`로 클라이언트는 자기 교실만 그린다. 그래도 **미검증**이다.
→ **완화:** Phase 1 직후 12슬롯을 전부 채워 **MicroProfiler(Ctrl+F6)**로 서버 heartbeat와 **모바일 실기기 FPS**를 측정한다. 기준: 서버 heartbeat < 16ms(33ms 초과 시 조사), 모바일 45FPS 목표(30 미만 시 조사).
→ **폴백:** 슬롯 6개 + 대기열, 학생 파트 7개 → 4개 축소, 미세 idle 트윈 제거.

**🔴 리스크 2 — 중반부 지루함 (72반 × 같은 룰)**
변주 축을 두 개만 쓰기로 했으므로 3~4학년 구간이 단조로울 수 있다.
→ **완화:** 교실 레이아웃 프리셋을 최소 6종 만들어 로테이션 + 방해물 조합을 반마다 섞는다. 3학년 플레이테스트에서 이탈이 보이면 그때 감시자 축(반장/CCTV)을 추가 검토한다. — *이 판단은 데이터를 보고 나중에 하면 되고, 지금 설계를 바꿀 필요는 없다.*

**🟡 리스크 3 — 한국 초등학교 에셋 조달**
로블록스 툴박스에 한국풍 학교 에셋이 거의 없다. 신발장·급훈 액자·조회대·태극기는 직접 만들어야 한다.
→ **완화:** MVP 아트 예산의 80%를 **교실 하나**에 몰아준다(가장 오래 보는 공간). 운동장은 5단계까지 회색 박스로 두어도 게임은 성립한다. 실물 사진을 텍스처로 쓸 땐 저작권 확인 필수.

3. 졸업 후 무엇을 하나? (뉴게임+ / 선생님 플레이 모드 / 명예의 전당 관람)

## 확정된 설계 결정 요약

| 항목 | 결정 |
|---|---|
| 멀티 구조 | 공용 서버(12명) + 개인 교실 인스턴스 |
| 맵 구조 | 교실 1개 템플릿 재사용, 복도는 실제 건설 |
| 한 판 길이 | 30초~1분 |
| 감지 룰 | 시야각 × 움직임 (+ 엄폐 레이캐스트) |
| 실패 페널티 | 해당 교실 문 앞 재시작, 진행도 유지 |

| 예고 신호 | 분필 소리 멈춤 + 어깨 들썩 |
| 이동 | 살금살금 / 걷기 / 달리기 3단계 |
| 성장 | 별 토큰 선택식 업그레이드 |
| 학년별 변주 | 바닥·사물 방해물 + 선생님 패턴 진화 (2축) |
| 저장 | DataStore 영구 이어하기 |
| 수익화 | 외형 + 편의 중심 |
| 운동장 | 로비 + 허브 (잠입 구간 아님) |
| 카메라 | 3인칭 고정 (어깨너머) |
| 클리어 조건 | 빈자리에 앉는 순간 즉시 |
