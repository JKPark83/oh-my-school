## 1. 배경

### 1.1 사용자가 짚은 문제(2026-10-01, 직접 플레이 뒤)

1. 2층 강당까지 지으면 끝이라 실제 플레이가 10분 안팎이다.
2. 졸업하면 처음부터라 「계속 만들고 꾸민다」는 느낌이 없다.
3. 한 층씩 쌓아 올려 높고 화려한 학교가 경쟁심을 줘야 한다.
4. 에셋·기구가 덜 정교하다. 학교에 있을 만한 장소·교실을 늘린다.

### 1.2 조사 요약

- 인기 타이쿤의 평균 세션은 16~29분, 첫 「완성」은 20~30분. 첫 완성에서 끝나는 게임은 없다.
- 비용 곡선은 단계마다 1.12~1.18배, 수입은 단계마다 1.08~1.12배가 보편적이다.
- 실제 10분에 끝난 원인: 코드는 학생 기여(`CONTRIB`)를 수입에 곱하는데 시뮬에는 없어서 가격표가 쌌다.

### 1.3 확정된 결정(질문 16개)

| # | 결정 |
|---|---|
| 1 | 졸업 시스템 폐기. 저장 데이터는 **초기화**(새 스토어, 마이그레이션 없음) |
| 2 | 3층부터 **층마다 방을 골라** 짓는다. 한 층 = 방 하나, **부품 4개**(①뼈대 ②큰 가구 ③소품 ④마무리 장식) |

| 5 | 새 방 12종: 미술실·컴퓨터실·방송실·요리실·댄스실·코딩로봇실·영어체험실·돌봄교실·교무실·전시실 + 옥상 전용 옥상정원·천문대 |

### 1.4 되풀이하면 안 되는 실패

2026-10-01 오전에 층 올리기를 한 번 지웠다. 이유는 「층을 사도 달라지는 게 안 보인다」(수입 0·학생 0·가구 1개)였다.
새 설계는 층마다 **수입 + 학생 + 방 안 가구 + 밖에서 보이는 색·간판**을 준다.

## 3. 층·방 규칙

### 3.1 `src/shared/Config/RoomConfig.luau`(새 파일, 층·방 수치의 단일 소스)

```lua
RoomConfig.FIRST_FLOOR = 3
RoomConfig.MAX_FLOOR = 30          -- 맨 위 층 번호(층 방 28 = 30 - 3 + 1). P2 실측으로 30 유지 확정(§5.2)
RoomConfig.PARTS = 4
RoomConfig.PART_NAMES = { "뼈대", "큰 가구", "소품", "마무리 장식" }
RoomConfig.PART_WEIGHTS = { 0.1, 0.2, 0.3, 0.4 }  -- 단계 가격을 부품 4개로 나누는 비율(첫 부품이 빨리 온다)
RoomConfig.LIST: { Room }          -- 12개
RoomConfig.STEPS: { { parts: { number }, income: number } }  -- 단계표(시뮬 산출, §4). 30행 = 층 방 28 + 옥상 방 2

export type Room = {
    id: string, name: string, kind: "floor" | "roof",
    student: string?,              -- 처음 완공하면 오는 학생
    wall: Color3, accent: Color3,  -- 외벽·포인트 색(빨강 계열 금지)
    icon: string,                  -- 간판·카드에 쓰는 이모지 한 글자
    seats: { Vector3 },            -- 방 로컬 좌표(발자국 중심·바닥 윗면 기준). [1] 이 그 방 학생 자리
}
```

| id | 이름 | 종류 | 학생 |
|---|---|---|---|
| `art` | 미술실 | floor | s16 서윤 |
| `computer` | 컴퓨터실 | floor | s15 건우 |
| `broadcast` | 방송실 | floor | s21 서하 |
| `cooking` | 요리실 | floor | s25 (새 학생) |
| `dance` | 댄스실 | floor | s26 (새 학생) |
| `robot` | 코딩로봇실 | floor | s20 은우 |
| `english` | 영어체험실 | floor | s19 지안 |
| `care` | 돌봄교실 | floor | s27 (새 학생) |
| `staff` | 교무실 | floor | s18 권도현 |
| `exhibit` | 전시실(공룡·행성) | floor | s23 금동이 |

함수: `stepOf(profile)`, `nextStep(profile)`(상한이면 nil), `partPrice(step, k)`, `incomeOf(profile)`(완공 단계 수입 합),

### 3.2 고르기 규칙

- 강당(14번째 시설)을 완공하면 층 쌓기가 열린다.
- `floor` 방: 아직 안 지은 종류가 남아 있으면 그중에서만 고른다. 10종을 다 지었으면 아무 것이나 또 고를 수 있다. 층 수가 `MAX_FLOOR` 면 못 고른다.
- `roof` 방: 종류마다 한 번. 옥상 방은 층 수를 늘리지 않고, 항상 **맨 위 옥상**에 그려진다(층이 올라가면 같이 올라간다).
- 수입·가격은 단계로 정해지므로 어떤 방을 골라도 손해가 없다. 방 선택은 모양·학생·도감을 고르는 일이다.

### 3.3 구매 흐름

1. 층 패드(§5.2)에 주인이 서면, `towerRoom == ""` 일 때 클라가 **방 고르기 패널**을 연다 → `ChooseRoom`.
2. 방을 고르면 패드가 부품 1의 가격을 보여 준다. 기존 패드와 같은 규칙으로, 올라서 있고 용돈이 되면 부품 1개를 산다(틱당 1개).
3. 부품 1~3: `towerParts += 1`, `FloorPart` 이벤트. 부품 1(뼈대)에서 서버 바닥판·지붕이 생긴다.
4. 부품 4: `floors` 에 방을 넣거나 `rooftop[id] = true`, `towerParts = 0`, `towerRoom = ""`, 수입 반영, 그 방 학생 지급(처음일 때), `FloorBuilt`, 리더보드 제출.
5. 층 방을 완공하면 주인이 그 층에 서 있을 때 축하 연출 뒤 새 옥상 도착 자리로 옮겨 준다(다음 방을 바로 고를 수 있게).

P2 구현: 층 패드 occupants 키는 `"tower"`(`Keys.TOWER_PAD_ID`). `FloorPart.floor` = 맨 위 층 + 1(옥상 방이면 0). 완공 순서 = floors/rooftop 갱신 → `PlotService.refreshTower` → `FloorBuilt` → 학생 지급 → `MissionService.onBuilt` → `LeaderboardService.submit(player, #floors)` → 4.5초(`CELEBRATE_DELAY`, EconomyService 로컬 상수) 뒤 옥상으로 → `syncNow` · 즉시 `save`. 방 고르기 패널은 패드에 올라서면 열리고, 닫았다가 다시 올라서면 다시 열린다. Studio 확인용 `DevCheat.BuildFloor(player, roomId)` = `EconomyService.buildRoom`.

### 3.4 수입·학생

- 초당 수입 = (Σ 완공 시설 income + Σ 완공 단계 income) × (1 + 학생 기여 합). 졸업 배율은 없다.
- `StudentConfig.Unlock.kind`: `"graduation"` 삭제, `"room"` 추가(`value` = 방 id). 친구 아이템(`"friend"`)은 `value` 없이 처음부터 진열되는 3명(s14·s17·s22)만 남는다.
- 학생은 28명이 된다(s25~s28 추가. 전용 메시 없이 `fallbackVariant + tint`). 새 학생 등급: s25·s27 평범, s26·s28 반장.
- 좌석: `Types.Seat.facilityId` 에 방 id 도 쓴다. 방 id 와 시설 id 는 겹치지 않는다. 방 좌석 위치는 `RoomConfig` 의 `seats`,
  층은 그 방이 **처음 지어진 층**(옥상 방은 맨 위 옥상)이다.
- `DecorConfig`: 졸업 횟수로 열리던 친구 아이템 6개는 학생 없는 `general` 로 바꾼다(`unlock` 필드 삭제, 종류별 개수 18/6/3). `priceOf(id)` 는 표 값 그대로.

## 4. 경제(시뮬 `docs/sim/sim-parts.py` 가 산출)

- 시뮬에 학생 기여(`CONTRIB`)를 넣는다. 졸업 경로는 지운다.
- **시설 50부품**: 활동형(스티커 55% 회수) 기준 14시설 완공 19~21분. 구매 간격은 5초에서 시작해 서서히 늘어난다.
- **단계표**: 단계 s 의 걸리는 시간 `t(s)` 는 s=1 에서 5분, 20층(s=18 안팎)에서 약 50분, s=20 에서 60분으로 서서히 늘고 그 뒤는 60분.
  활동형으로 20단계까지 총 8~9.5시간(시뮬 8:39). 단계 수입은 완공마다 배율 전 수입(Σ income)이 1.10배가 되게 잡는다.
  13단계부터는 새 학생이 없어 총 수입도 1.10배다. 1~12단계는 방 학생 기여가 함께 붙어 총 수입이 1.11~1.33배 뛰지만,
  단계 가격이 직전 수입 × `t(s)` 라 걸리는 시간은 `t(s)` 그대로다.
- 단계 가격 = 직전 활동형 초당 수입 × `t(s)`, `PART_WEIGHTS` 로 4등분, 유효숫자 2자리 반올림.
- `PRICE_SCALE`·`GRAD_STEP`·`startCoins(g)`·`giftCoins(g)` 의 회차 인자는 지운다(상수가 된다).
- `check-config.py` 가 시뮬 표와 `FacilityConfig`·`RoomConfig`·`DecorConfig` 를 대조한다.

> 알려 둘 점: 「부품 4개」와 「20층까지 8~10시간」을 함께 지키면 위층의 부품 간격은 1~10분이 된다(초반 10~60초를 유지할 수 없다).
> 첫 부품을 싸게(10%) 해서 방을 고르자마자 뼈대가 서게 하고, 기다리는 동안은 스티커·꾸미기·방문을 한다.

## 5. 월드

### 5.1 좌표(`PlotLayout`, 부지 로컬)

- `TOWER_BASE_Y = 37.2`(강당 지붕 윗면), `FLOOR_STEP = 19`. n층 바닥 윗면 y = `TOWER_BASE_Y + (n-3) × FLOOR_STEP`.
- `TOWER_FOOTPRINT = { x0 = -20, x1 = 20, z0 = -35, z1 = -5 }`(40×30).
- `ELEVATOR_XZ = Vector2(17.5, -17.5)`(계약 이름 `ELEVATOR` 대신. 3층 이상·옥상 같은 x·z). 도착 자리는 `ARRIVAL_OFFSET (0,0,4)` = (17.5, -13.5).
- `TOWER_PAD_XZ = (17.5, -8.5)`: 층 패드 x·z. 가구 금지 구역 `TOWER_CLEAR = { x0 = 12.5, x1 = 20, z0 = -22.5, z1 = -5 }`(엘리베이터 칸·도착 자리·패드).
- 2층(강당)과 1층(현관)에 엘리베이터 타는 곳을 하나씩 둔다. P2: `ELEVATOR_F1 = (-10, 0, 5)`(현관), `ELEVATOR_F2 = (17.5, 18.2, -17.5)`(강당 바닥, 위층과 같은 x·z). `PlotLayout` 에 겹침 assert 가 있다.

### 5.2 서버 파트(부지 ≤ 500 예산)

`Geometry/Tower.luau` 가 부지 모델 안 `Tower` 폴더를 짓는다. 강당이 없으면 비운다.

| 파트 | 수 | 비고 |
|---|---|---|
| `FloorNN` 바닥판 | 층마다 1 | 엘리베이터 프롬프트는 바닥판의 Attachment `Elevator` 안 `ElevatorPrompt`(앵커 파트 없음) |
| `Roof` 꼭대기 판 | 1 | 맨 위 층의 천장이자 옥상 바닥. 층이 0 이면 강당 지붕이 그 자리 |
| `TowerPad` | 1 | 항상 **옥상 바닥**(짓는 중이면 짓는 층 바닥) 위. `PAD_TAG`, `FacilityId = "tower"` |
| `ElevatorF1`·`ElevatorF2` 앵커 | 2 | 투명, 프롬프트 |
| `RoofRail1~4` | 4 | `Roof` 둘레 투명 충돌 벽. 옥상 낙하 방지는 서버가 맡는다(클라 난간은 모양만, 먼 부지는 안 그림) |

- 합계: 층 수 + 8. `MAX_FLOOR` 30 이면 28 + 8 = 36, 14시설 440 과 합쳐 476 ≤ 500.
- **P2 Studio 실측**(한 부지, 강당까지 완공): 부지 전체 448(0층) · 458(10층) · 468(20층) · 476(28층 + 옥상 방 2), Tower 폴더 8 · 18 · 28 · 36. 서버 Heartbeat 처리 0.08~0.09ms. 클라 내 부지 TowerFx 87 · 137 · 177(옥상 방 2 포함 211) 파트, 클라 Heartbeat 스크립트 0.72~0.84ms. 12부지 × 28층 × 5 ≈ 1,700 외관 파트가 최악. 클라 프레임 시간은 Mac 잠금으로 못 쟀다(실기기 확인 대기). 결론: `MAX_FLOOR` 30 유지.
- 서버 탑 파트에는 `FADE_TAG` 를 달지 않는다(가림은 클라 `TowerFade`).

- 층 방을 짓는 중(`towerParts ≥ 1`)이면 그 층 바닥판 위에 지붕을 한 층 올린다(뼈대가 서면 옥상이 올라간다). 패드는 짓는 층 안에 남는다.
- 벽·창·간판·가구·난간·깃발·옥상 방은 전부 **클라가 그린다**.

### 5.3 클라 렌더(`TowerRenderController`)

- 12부지 모두 PlotState 어트리뷰트(`Floors`·`Rooftop`·`TowerRoom`·`TowerParts`·`Rank`)를 읽어 그린다.
- 층 외관(모든 층): 방 색 외벽 4면 + 창 + 방 이름 간판(남쪽 면). 층당 ≤ 10 파트. P2 구현: 가까운 부지 층당 5 파트, 먼 부지 층당 1 파트(통짜 블록). 로컬 폴더 `Workspace.TowerFx/PlotNN`.
- 방 안(로컬 플레이어가 있는 층과 위아래 1층만): `src/client/Rooms/<id>.luau` 레시피(P2 는 `Rooms/init.luau` 의 `Rooms.get(roomId)` 가 12종 공통 임시 레시피를 돌려준다. 방별 파일은 P3). 부품 단계별로 그린다
  (`big` = 큰 가구, `props` = 소품, `finish` = 마무리 장식). 방 하나 ≤ 60 파트. 메시는 `PropAssets` id, 0 이거나 실패하면 파트 폴백.
- 짓는 중인 층: 부품 0 = 반투명 실루엣, 1 = 뼈대(벽·창), 2 = +큰 가구, 3 = +소품, 4(완공) = +마무리·간판.
- 옥상: 난간(모양만, 충돌은 서버 `RoofRail`), 꼭대기 깃발(`Rank` 1 금·2 은·3 동·그 밖 학교 색), 옥상 방.
- 카메라와 캐릭터 사이 벽은 투명해진다. P2 구현: 클라 탑 파트는 `TowerRenderController` 의 `TowerFade` 가 따로 흐린다(서버 `FADE_TAG` 아님).

### 5.4 엘리베이터

- 타는 곳의 프롬프트(`E`)를 누르면 클라가 층 버튼 패널을 연다: `1층`, `2층 강당`, `3층 미술실` …, `옥상`. 큰 버튼, 스크롤. P2: 짓는 중인 층은 「n층 공사 중」 행으로 보인다.
- `RideElevator(plotId, floor)` → 서버가 도착 자리로 옮긴다(`PlotService.teleport`). 방문객도 탈 수 있다.

### 5.5 카메라

- `ZOOM_MAX` 를 키워 학교 전체가 보이게 한다(P2: 120). 층 완공 축하는 학교 높이에 맞춰 물러나 한 바퀴 돈다(약 4초, 주인 화면만).

## 6. 경쟁·수집

### 6.1 높이 순위

- `LeaderboardService`: OrderedDataStore `SchoolFloors`(Studio `_Dev`), 값 = 완공 층 수(`#floors`). 제목 「높은 학교」, 행 `{순위}. {DisplayName}  {n}층`.
- 같은 서버 안 순위를 `ATTR_RANK` 에 쓴다(층 수 내림차순, 같으면 먼저 지은 쪽). 꼭대기 깃발 색이 바뀐다.

### 6.2 「멋져요」

- 남의 부지 안에 있으면 HUD 에 「👍 멋져요」 버튼이 뜬다. 누르면 `Like`. 주인에게 「○○ 님이 멋져요를 보냈어요!」(주인 화면만).
- 받은 수는 교문 간판과 HUD 에 보인다. 줄어들지 않는다. 싫어요는 없다.

### 6.3 도감

- 기존 학생 도감에 **방 도감** 탭을 더한다(12칸, 지은 방은 색, 안 지은 방은 실루엣과 이름). 지은 방은 `floors`·`rooftop` 에서 계산한다(따로 저장하지 않는다).
