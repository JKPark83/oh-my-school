1. 출시를 막는 것

먼저 할 일

  • 비공개로 첫 게시 — Studio 에서 File → Publish to Roblox As… 로 개인 계정에 새 게임으로 올리고, 공개 범위는 비공개로 둔다

    아직 PlaceId 가 0 이다. 1-1 실기기, 1-3 부지 넘겨받기, 1-4 라이브, 1-5, 1-6 이 이 게시를 기다린다. 게시한 뒤 알려 주면 PlaceId 와 서버 쪽을 이어서 확인한다.

1-1. 실기기 성능

갤럭시 A34 / iPhone 11 급 폰. 비공개로 게시한 게임에 폰의 로블록스 앱으로 들어간다.

  • FPS 45 이상 — 자기 부지 14개를 다 지은 상태(1회차 약 19분)에서 교실·강당 안을 걷고, 광장에서 이웃 부지를 바라볼 때

    채팅창에 /console 을 쳐 개발자 콘솔을 연다. 콘솔이나 설정의 성능 통계 중 보이는 쪽에서 FPS 를 읽는다. Client 로그에 [StudentRender] 저사양 다이얼 켬: 평균 N FPS 가 찍히면 이미 30 FPS 아래로 떨어졌다는 뜻이다.

  • 메모리 — 개발자 콘솔 Memory 탭에서 클라이언트 전체 ≤ 600MB, 그중 텍스처(NPC 19장) ≤ 40MB 정도인지

  • 측정값으로 두 가지를 정한다 — 숫자를 알려 주면 코드와 기획서를 같이 고친다

    결과광원(부지당 13, 천장 SurfaceLight)학생 메시(약 9,300~9,900 tri, 1024² 텍스처)
    45 FPS 이상, 메모리 여유13 유지그대로 두고 기획서 §12.1 수치를 실측에 맞게 고친다
    45 FPS 미만부지당 ≤ 6 으로 줄인다maxTriangles 6000 으로 다시 만든다

1-3. 2인 테스트

기획서 §7.5 점검표. 방문객이 주인을 늦추는 것이 하나도 없어야 한다. Studio Test 탭 → Clients and Servers, 플레이어 2. A 는 주인, B 는 A 부지를 찾아간 방문객이다.

  • 패드 — B 가 A 의 패드 위에 서 있어도 A 의 자동 구매가 막히지 않고, B 에게는 반응이 없다

  • 노란 스티커 — B 가 밟아도 아무 일 없음

  • 하늘색 별 이번에 고침

    • B 가 밟으면 B 스티커판 +1, B 의 미션 1 「스티커 30개」도 +1
    • 별 위에 서서 비비거나 여러 번 지나가도 같은 별은 한 번만 센다
    • 한 부지에서 60초에 최대 2개. B 화면에서만 별이 사라지고 A 화면에는 그대로 보인다
    • A 가 자기 별을 밟으면 반응 없음

  • 교장 의자 이번에 고침 — B 가 A 의 교장 의자에 앉으면 바로 일어나 옆으로 비켜난다. A 는 곧바로 앉을 수 있고 미션 3 이 된다

  • 졸업 중 방문객 — B 가 A 의 강당 안에 있을 때 A 가 졸업한다

    색종이·컷·소리는 A 화면에만 나오고, 철거 때 B 가 튕기거나 끼지 않는다.

  • 서로 부딪히지 않음 — 문·교문·캐릭터끼리

  • 튜토리얼 — 새 계정의 발자국·빛기둥·화살표·카메라 팬이 방문객 때문에 꼬이지 않는다

  • 부지 넘겨받기 이번에 고침 라이브 — Studio 는 재입장이 안 되니 라이브에서 계정 두 개로 한다

    A 가 서버를 잡아 두는 동안 B 가 스티커를 몇 장 줍자마자(15초 안에) 나갔다가 곧바로 다시 들어온다. B 부지의 노란 스티커가 하나도 빠짐없이 다시 뜨는지 본다(책상 3장, 복도·운동장을 지었으면 각각 +2·+3).

1-4. 실제 DataStore

Studio 에서 Game Settings → Security → Enable Studio Access to API Services 를 켜고, ServerScriptService 에 불리언 어트리뷰트 UseLiveDataStore = true 를 단다. 출력에 [DataService] PrincipalProfile_Dev 가 Mock 없이 찍혀야 한다.

  • 이어하기 — 시설 몇 개 짓기 → 정지 → 다시 플레이: 그대로 이어진다

  • 졸업 중 퇴장 — 졸업 홀드를 끝내자마자(8초 안에) 정지 → 다시 플레이: 시설 0 · 졸업 +1 · 용돈 14

  • 리더보드 분리 — Studio 졸업은 Graduations_Dev 에만 들어간다. 라이브 광장 졸업왕 보드에 Studio 기록이 보이지 않아야 한다

  • 뒷정리 — 끝나면 UseLiveDataStore 어트리뷰트를 지운다(평소 Studio 는 Mock)

  • 서버 옮기기 라이브 — 한 서버에서 나가자마자 다른 서버로 들어가도 진행이 이어진다

    「다시 들어와 주세요」로 킥되면 다시 들어왔을 때 이어지는지 본다(세션 잠금).

1-5. Creator Dashboard 설정

  • 게시 계정 — 메시는 게임 소유자 개인 계정에 올라가 있다. 그룹 게임으로 옮기면 전부 깨지니 같은 계정으로 게시한다

  • Experience Guidelines 설문 — 기획서 §12.2 표대로 답한다

    • 유료 무작위 없음, 무료 무작위 있음(확률 상시 표시)
    • 자유 텍스트 없음, 폭력 없음, 도박 묘사 없음, 외부 링크 없음, 음성 끔

  • 등급 스크린샷 — 등급이 「전체(Minimal)」로 나온 화면을 남긴다(W8 게이트)

  • 채팅 — 음성 채팅 끔. 채팅은 TextChatService 기본

  • 서버 — 인원 12, 비공개 서버 끔

  • 보안 — HTTP 요청 끔, 서드파티 텔레포트·판매 끔

  • 기기 — 폰 · 태블릿 · 컴퓨터

  • 스토어 페이지 — 한국어 설명, 장르, 원본 언어 한국어

    아이콘 assets/branding/icon.png, 썸네일 thumbnail-a-campus.png → thumbnail-b-collection.png 순서.

  • 소프트 런치 — 비공개로 확인한 다음 공개로 바꾼다. 문제가 생기면 Version History 에서 되돌린다

1-6. 첫 라이브 서버 로그

라이브 서버에 들어가 개발자 콘솔 Server 로그를 본다.

  • [DevCheat] 줄 없음 — Studio 에서만 켜진다

  • [SoundController] 경고 없음

2. 눈으로 볼 것

2-1. 전용 메시 8명

Studio 에서 플레이 → Test 탭에서 보기를 Server 로 바꾼다 → 명령 바에 아래를 붙여 넣는다. 광장 가운데에 앞줄은 선 모습, 뒷줄은 의자 높이 블록 위에 앉은 모습이 선다. Client 로 돌아가 걸어가서 본다.

명령 바 · Server 보기
local RS = game:GetService("ReplicatedStorage")
local CB = require(RS.Shared.CharacterBuilder)
local SC = require(RS.Shared.Config.StudentConfig)
local DEDICATED = { HAYUL = true, DOHYUN = true, JIAN = true, EUNWOO = true, SEOHA = true, COSMO = true, GEUMDONG = true, BAEKHO = true }
local old = workspace:FindFirstChild("MeshLineup") if old then old:Destroy() end
local lineup = Instance.new("Model") lineup.Name = "MeshLineup" lineup.Parent = workspace
local origin = CFrame.new(0, 0.15, 30) -- 광장 바닥
local i = 0
for _, row in SC.LIST do
  if DEDICATED[row.mesh] then
    i += 1
    local x = (i - 4.5) * 5
    local cfg = CB.studentConfig(row.id)
    cfg.sitting = false -- 앞줄: 선 모습
    local stand = CB.build(row.id .. "_stand", origin * CFrame.new(x, 0, 0), cfg)
    if stand then stand.Parent = lineup end
    cfg.sitting = true -- 뒷줄: 의자 면 높이 반투명 블록 위에 앉은 모습
    local seat = origin * CFrame.new(x, 0, 8)
    local block = Instance.new("Part")
    block.Anchored = true
    block.Transparency = 0.5
    block.Size = Vector3.new(3, CB.SIT_HIP * cfg.scale, 3)
    block.CFrame = seat * CFrame.new(0, block.Size.Y / 2, 0)
    block.Parent = lineup
    local sit = CB.build(row.id .. "_sit", seat, cfg)
    if sit then sit.Parent = lineup end
    print(row.id, row.name, stand and stand:GetAttribute("Variant"), sit and sit:GetAttribute("Variant"))
  end
end

  • 앉은 높이 — 엉덩이가 블록 윗면에 맞는다. 특히 도현(hip 1.05)과 백호(hip 1.00)가 뜨거나 파묻히지 않는지

  • 지안 — 땋은 머리와 왼팔이 몸통에 붙어 있다

  • 소품 — 메시에 붙어 함께 나온다(하율 금테 안경, 도현 트로피, 지안 책, 은우 고글, 서하 바이올린 등)

  • 방향 — 도현·은우·백호는 -Z 를 보고 생성했다. 왼팔(ArmLeft)이 캐릭터의 왼쪽(-X)에 있고 손 들기가 오른팔로 된다

  • 전설 — 코스모·금동이·백호의 크기와 파티클이 과하지 않다

  • 교실 좌석 — 실제 교실 좌석에서도 본다. 뽑기는 DevCheat.GiveTickets:Invoke(player, 50)

2-2. 졸업식·브랜딩

  • 졸업식 12초 — 강당 좌석에 학생이 앉아 있고, 학사모·색종이·교실 컷이 어색하지 않다

  • 썸네일과 게임의 차이 — 받아들일지 정한다

    • 썸네일의 금동이는 왕관, 게임 메시는 금색 리본 올림머리다
    • 썸네일 캐릭터는 일반형이다

  • assets/branding/README.md 를 한 번 읽어 본다 — 예전 썸네일 2장은 지웠다

3. 아이 테스트

W7 게이트. 7·9·11세 각 1명, 각 30분 이상.

Studio 플레이(Mock 이라 매번 새 계정)나 라이브 새 계정으로 한다. 도와주지 말고 옆에서 보기만 한다. 서버 출력에서 [Metrics] 줄을 모아 보내 주면 판정과 튜닝을 한다.

로그 줄게이트
5분 · 시설 N(≥7) · 전학생 N(≥8, 뽑기로 N) · 뽑기 N(≥4) · 미션 N(≥2) → 통과/미달통과
30분 · 시설 N/14 · …14/14 이거나 이미 졸업
첫 뽑기 m:ss(≤2:00 …)2:00 이하
요약 · … 회수율 N% …40% 이상
요약 · … 패드 3초 미만 N회(살 돈 있었음 N)반복되면 패드 반경 6 → 8

  • 7세 — 30분 이상 플레이하고 [Metrics] 줄을 모은다

  • 9세 — 30분 이상 플레이하고 [Metrics] 줄을 모은다

  • 11세 — 30분 이상 플레이하고 [Metrics] 줄을 모은다

  • 눈으로도 본다 — 로그에 안 남는 것

    • 접수대를 스스로 찾는가
    • 패드 위에 서 있어야 한다는 걸 아는가
    • 전설이 나왔을 때 반응이 어떤가
    • 어디서 지루해하는가
    • 글자를 못 읽어 막히는 곳이 있는가(1학년)

  • 미달이면 — 기획서 §5.7 다이얼(과 §13.3 대응표)만 바꾼다

    sim-final.py 와 EconomyConfig 를 같이 고치고 check-config.py 로 맞춘다. 요청하면 처리한다.
