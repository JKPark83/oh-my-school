## 1. 한 줄 컨셉 + 30초/5분/30분 루프

**한 줄 컨셉**: 빈 교실 하나를 물려받은 꼬마 교장이 칭찬스티커를 주워 학교 한 동을 짓고, 전학생 24명을 모아 졸업식을 열고, 다음 회차에 더 큰 학교를 다시 짓는 한국 초등학교 타이쿤.

**핵심 규칙 한 가지(7세가 배우는 유일한 규칙)**: 구매 패드 위에 서 있으면 링이 차는 순간 시설이 솟는다. 링이 이미 찼으면 밟는 순간. 시설이 솟으면 전학생이 그 방 문으로 걸어 들어와 앉는다.

**수입 공식**: 초당 수입 = Σ(지은 시설 초당 수입) × (1 + Σ재학생 기여) × (1 + 0.5 × 졸업 횟수)

**재화 2종**: 용돈(코인, 시설·스킨 구매) / 입학원서(뽑기권 1장 = 뽑기 1회).

### 1.1 30초 루프 — "줍고, 서고, 온다"
1. 앞마당·복도·운동장의 칭찬스티커(노란 원판, 15초 리스폰, 최대 8개)를 밟아 줍는다. 6초 안에 연달아 주우면 콤보(효과음 피치 상승, 5콤보마다 스티커판 +1칸).
2. 다음 시설 패드의 링 게이지(용돈 ÷ 가격)가 차는 것을 본다. HUD 의 「다음 시설」 카드가 같은 게이지와 예상 초를 보여 준다.
3. 링이 100%가 되면 패드가 초록으로 펄스 → 밟는다(또는 이미 위에 서 있다) → 시설이 땅에서 솟고, 그 시설의 전학생이 자기 방 문으로 걸어 들어와 앉는다. 원서 +1장.
4. 칭찬스티커판 60칸이 차면 원서가 튀어나온다(원서 아이콘이 판에서 HUD 로 날아감).

### 1.2 5분 루프 — "학교가 커진다"
- 5분 안에 시설 8개(책상~보건실), 시설 학생 8명 + 뽑기 학생 2명(채원·하율, 중앙값), 원서 10장(시설 8 + 중복 환급 2) + 미션 원서 2장. 0:55 에 첫 뽑기 유도(현관 뽑기 기계, 1:05 첫 카드), 1:47 교실2, 2:24 급식실, 3:11 도서관, 4:13 보건실(§5.2 중앙값).
- 시설마다 자리(좌석)가 늘고, 전학생은 도감표에 정해진 자리(§4.1)에 앉는다. 도감 카드가 한 장씩 뒤집힌다.
- 뽑기: 원서 1장 = 1회. 반장 75% / 전교1등 22% / 전설 3%. 50장째는 전설 확정(천장 링 상시 표시). 같은 등급 안에서는 아직 없는 친구가 먼저 온다. 중복은 스티커판 칸으로 돌려준다(반장 12·전교1등 24·전설 60칸)—판이 넘치면 그 자리에서 원서가 튀어나온다.

### 1.3 30분 루프 — "졸업하고 한 번 더"
- 활동형(스티커 55% 회수) 기준 **18분 49초**(10%~90% 15:13~19:23)에 14번째 시설 강당이 선다. 1회차 안에 코스모를 뽑은 절반은 16:17, 못 뽑은 절반은 18:56. 강당 단상의 졸업 종 → 확인 화면(남아요 / 새로 지어요) → 1.5초 홀드 → 12초 졸업식(강당 착석, 학사모 던지기, 색종이) → 「졸업 1회!」 도장.
- 졸업 후: 시설 14개와 용돈만 새로 시작한다(자리에는 30% 실루엣이 남는다). 도감·스킨·원서·스티커판·미션 진행·졸업 배율은 남는다. 졸업 1회에 전교1등 권도현이 확정 전학, 회차마다 뽑기 풀에 새 얼굴 1명 해금(졸업 8회까지).
- 2회차는 시설값 ×1.4, 수입 ×1.5(졸업) × 재학생 배율로 시작한다. 재학생 배율은 코스모 보유 여부로 갈린다(각 50%):
  - 코스모 보유 ×3.50: 복도 0:34, 급식실 1:07, 도서관 1:30, 보건실 2:04 → 강당 **10:49**.
  - 코스모 미보유 ×2.90: 복도 0:41, 급식실 1:20, 도서관 1:48, 보건실 2:28 → 강당 **13:03**(이 절반의 반은 2회차 안에 코스모를 뽑는다).
- 3회차 10:54, 9회차 20:06, 10회차 24:22(모두 중앙값). 도감 24명 완성 중앙값 9회차(누적 활동 플레이 131분, 90% 157분). 완성 뒤에도 졸업 횟수(광장 리더보드)와 스킨 4종 × 14 시설이 남는다. 도감 25번째 칸은 「예약석 ?」(출시 후 첫 업데이트).
- 시뮬은 뽑기 패널·꾸미기·구경에 쓰는 시간을 세지 않으므로 실제 1회차는 20~23분이다(세션 20~30분 안).

### 3.2 스킨 규칙
- 스킨은 모델이 아니라 `SkinConfig` 한 행(주색 1 + 부색 1 + 재질 1)이다. 지오메트리는 스킨과 무관하게 동일하므로 시설 14개 × 4 = 56 조합이 아니라 데이터 56행이다.
- 가격: A 무료. B = 시설 기본가 × 0.5 × 1.4^N. C = 시설 기본가 × 1.0 × 1.4^N. D = 시설 기본가 × 1.0 × 1.4^N + 졸업 1회 이상. 한 번 사면 영구 보유, 졸업해도 유지. 적용은 무료·무제한.
- 구매·적용 UI: 지은 시설 문 옆 페인트 롤러 팻말(BillboardGui 56px, `AlwaysOnTop`, 자기 부지에서만 보임)을 탭 → 하단 시트에 견본 4칸. 견본에는 가격 대신 링 게이지(용돈 ÷ 가격, 작은 가격 병기), D 는 「졸업 1회」 자물쇠. 3초 미리보기(클라이언트 전용), 「적용」 → `SetSkin`.
- 서버는 `Skins` 어트리뷰트만 바꾸고 색 적용은 클라이언트가 한다(자기 부지·남의 부지 같은 코드).
- 근거: 스킨값을 시설값과 같은 자릿수로 두면 "시설 하나 더 짓는 값"으로 체감되고 인플레이션을 자동 추종한다. 시뮬레이션은 스킨을 사지 않는 그리디 구매라 회차 시간에 영향이 없다.

### 3.3 시설 지오메트리
- 시설 1개 = `BuildKit.part` 로 조립한 앵커드 파트 ≤ 25개, ≤ 5,000 tri. CSG 없음. 벽·지붕에는 `Keys.FADE_TAG` 를 붙여 카메라가 안을 볼 수 있게 한다.
- `src/server/Geometry/<facilityId>.luau` 하나에 `build(plotCFrame, skin) → Model` 함수 하나. 좌석은 모델 안 `Seats` 폴더의 Attachment `S01`~`S06`(강당은 `S01`~`S25`, 스킨과 무관하게 동일 위치).
- 서버는 모델을 `Transparency 1` + 어트리뷰트 `Built = true` 로 넣는다. 등장 애니메이션(Y -6 → 0)은 클라이언트가 `ChildAdded` 로 받아 재생한다(§9.2).
- 강당·체육관·운동장 3개는 신규 메시 없이 파트만으로 만든다. `generate_mesh` 는 전학생 8명에만 쓴다.
- 부지 서버 파트 예산 ≤ 500: 껍데기·담장·패드·접수대·계단 120 + 시설 14 × ≤25 = 350 → 470. 학생 NPC 는 클라이언트 전용이라 서버 파트에 들어가지 않는다(§12.1).

### 4.3 좌석 규칙(`Shared/Seats.luau`, 순수 함수)
- 자리는 §4.1 의 고정값 `StudentConfig[id].seat = { facilityId, index }` 다. 동적 배정은 없다.
- `Seats.seatOf(studentId, builtFacilities) → { facilityId, index } | nil`: 그 학생의 시설이 지어져 있으면 자리, 아니면 nil. nil 인 학생은 "등교 전"으로 렌더하지 않는다(수입 배율에는 항상 전원 반영).
- 시설이 서는 순간 그 방에 자리가 있는 보유 학생 전원이 그 방 문으로 걸어 들어온다(자기 부지: 걷기, 남의 부지·재접속: 페이드 인). 졸업 뒤 다시 지을 때도 같은 코드가 "돌아오는" 연출을 만든다.
- 시설별 자리 요약: 교실1 S01~S06 = s01 s02 s03 s04 s14 s17 / 교실2 S01~S06 = s22 s05 s18 s15 s16 s23 / 급식실 S01~S04 = s06 s19 s20 s21 / 도서관 S01~S03 = s07 s24 s25 / 보건실 S01 = s08 / 과학실 S01~S02 = s09 s11 / 음악실 S01~S02 = s10 s12 / 교장실 S01 = s13.

### 4.4 메시 파이프라인
- 신규 8명: `generate_mesh` 로 기존과 같은 5 파트(Head·Torso·ArmLeft·ArmRight·Legs)를 뽑았다. 대표 소품(안경·트로피·책·고글·바이올린·헬멧·금 리본·호랑이 후드)은 메시에 구워 넣었으므로 전용 메시로 그릴 때는 소품 파트를 붙이지 않는다. `CharacterAssets.luau` 에 `HAYUL`, `DOHYUN`, `JIAN`, `EUNWOO`, `SEOHA`, `COSMO`, `GEUMDONG`, `BAEKHO` 항목이 있고 `StudentConfig[id].mesh` 가 이 키를 가리킨다. 지안은 생성기가 땋은 머리를 팔로 잘라서 `Braid` 파트가 따로 있다(왼팔은 Torso 에 붙음).

### 5.3 칭찬스티커 기여
- 스티커 가치 = max(10 × 1.4^N, 초당 수입 × 1.2초). 1회차 처음 1분은 10원(스티커 3개 = 칠판 반값), 그 뒤로는 항상 "수입 1.2초어치" → 줍기의 상대 가치가 회차·시설과 무관하게 일정하다.
- 활동형 총수입의 30%가 스티커. 스티커를 전혀 안 주우면 1회차가 7분 늘어난다(18:49 → 25:50). 줍기는 "필수는 아니지만 확실히 빠른" 선택.
- 황금 스티커: 서버가 `(stats.totalStickers + 1) % 12 == 0` 이면 다음에 리스폰하는 스티커에 `Gold = true` 어트리뷰트를 붙인다(그래서 미리 금색으로 보인다). 가치 ×5. 기대값을 4/3배로 올리고 분산을 준다.
- 스티커 파트는 서버가 `Collected` 어트리뷰트를 먼저 세팅하고 `CanTouch = false` 로 끈 뒤 15초 후 재활성한다. 클라이언트 예측의 확인 채널은 이 어트리뷰트다(§9.1).

**뽑기 규칙(패널 요소: 「뽑기」 버튼 · 점판 · 천장 링 · X)**
- 원서 1장 = 1회. 확률은 10×10 점판(파랑 75 · 보라 22 · 금 3, 점 8px, 96×96) + 「100번 뽑으면 반장 75 · 전교1등 22 · 전설 3」 한 줄로 보여 준다. 10만 회 실측 74.4 / 21.8 / 3.8(천장 포함).
- 천장: 전설 없이 49장이면 50장째 전설 확정. 코스모 실루엣 둘레의 50칸 링이 차오르고 작은 「n장 더」를 병기한다. 전설이 나오면 0으로.
- 풀: 그 시점 졸업 횟수로 해금된 뽑기 학생만(§4.2). 같은 등급 안에서 미보유 우선, 모두 보유면 그 등급 중 무작위 → 중복.
- 중복: 카드에 「×n」 도장 + 패널 안 스티커판 미니 게이지 「+12칸」(반장 12 · 전교1등 24 · 전설 60) 2초 애니메이션 + 그 학생 NPC 에 소품 파트(×2 배지, ×3 모자, ×4+ 가방). 판이 넘치면 원서가 그 자리에서 튀어나온다. "꽝"이 없다.
- 원서 0장: 「뽑기」 회색 비활성 + 「원서가 없어요」 + 원서 얻는 길 아이콘 2개(패드·스티커판). 「다시!」는 원서 ≥1 일 때만 활성. 클라이언트는 tickets<1 이면 `RollGacha` 를 보내지 않고, 서버는 tickets<1 요청을 무시한다.
- 연출 제한: 캡슐 흔들림 + 카드 뒤집기만. 레버·릴·코인 투입구·잭팟 불빛·카지노 소리 없음. 공개 전 등급 힌트·색 흔들림·니어미스 없음. 결과까지 ≤2.0초. 「확인」이 주버튼, 「다시!」는 보조.
- 구현: `local rng = Random.new()` 를 StudentService 안에 하나 둔다. RATES/PITY/DUPE_CELLS 는 `Shared/Config/GachaConfig.luau` 한 곳. W3 에 Luau 10만 회 롤 테스트(천장 끄고 오차 <0.5%, 천장 포함 전설 3.5~4.0%).
- 원서 용돈 구매·10연속·★ 중복 계수·회차별 확률표·천장 3종·Robux 경로는 없다.
- 근거(3%·천장 50, `--tune`): 1회차 안에 코스모를 만날 확률 50%, 못 만나도 3회차 안 100%. 2%·천장 60은 1회차 36%로 첫 세션의 "전설 봤다" 비율이 너무 낮고, 5%·천장 40은 70%라 전설이 흔해진다. 3%·천장 30은 46%로 큰 차이가 없어 천장은 50을 유지한다.

## 6. 졸업 규칙 + 일일 미션

### 6.1 졸업 조건·절차
1. 조건: 시설 14/14(강당 완공). 강당 단상의 졸업 종 위에 빌보드 버튼 「졸업하기」가 자기 부지에서만, 14/14 일 때만 보인다(클라이언트가 부지 어트리뷰트로 판단).
2. 탭 → 전체 화면 확인: 졸업모 아이콘 128px + 「제 N회 졸업식」. 두 줄 아이콘: **남아요** 도감·스킨·원서·스티커판·졸업 배율 / **새로 지어요** 시설(실루엣 + 반짝임 아이콘)·용돈. 「졸업식 시작」 260×72(1.5초 홀드 링) / 「아니요」 160×56. X 버튼도 있다.
3. 홀드 완료 → `Graduate` → 서버 `GraduationService.graduate(player)`:
   - 검증: 14/14, `graduating[userId] == nil`, 마지막 졸업 후 10초.
   - **원자적 프로필 변경(한 함수, yield 없음)**: `graduations += 1`, `facilities = {}`, `coins = 10 × 1.4^graduations`, 졸업 확정 학생 추가(1회 s18 도현, 5회 s23 금동이), `skinsApplied`·`skinsOwned`·`tickets`·`board`·`pity`·`missions` 유지.
   - `graduating[userId] = true` → `DataService.save(player)` 즉시(실패 시 warn + 1회 재시도; 메모리 프로필은 이미 바뀌었고 ProfileStore 자동 저장이 뒤따른다) → 저장 성공 뒤 `LeaderboardService.submit(userId, graduations)` → `GameEvent{kind=Graduated, plot, graduations, newStudentId}` 서버 전체 방송(구경꾼도 색종이를 본다).
   - 플래그가 켜진 동안 그 플레이어의 패드 자동 구매·`SetSkin`·`RollGacha`·스티커 줍기·별 줍기를 무시한다.
   - **8.0초 뒤** 월드 철거: 시설 모델 제거, `Facilities` 어트리뷰트 갱신, 스티커 스폰 3으로, 시설 자리에 30% 투명 실루엣 14개(1파트씩) → `graduating[userId] = nil`. PlayerRemoving 이면 즉시 철거. 8초는 연출을 위한 대기일 뿐 프로필과 무관하다.
4. 클라이언트 졸업식 12초(§9.5). 7.5초에 페이드 시작, 8.0초 완전 검정(= 서버 철거), 9.0초 교실1 컷. 철거가 화면에 보이지 않는다.
- 근거(원자적 저장): v1.0 은 "8초 뒤 초기화"라 그 사이 나가면 졸업 횟수만 오르고 시설이 남는 무한 증식 경로가 있었다. 프로필 변경과 저장을 한 번에 끝내면 그 경로가 닫힌다.

- 교장 의자는 주인 전용: `Occupant` 의 플레이어가 OwnerId 가 아니면 `Humanoid.Sit = false` + `Seat.Disabled` 1초. 방문객이 미션을 대신 채우거나 자리를 막을 수 없다.

### 7.4 카메라(기존 `CameraController` 재사용)
- 로블록스 기본 3인칭 카메라 그대로. `CameraController` 는 기본 카메라의 래퍼이므로 수정은 두 곳: `CAMERA_DISTANCE 11 고정`(현재 `CameraMinZoomDistance = CameraMaxZoomDistance = 11`) → `MinZoom 8 / MaxZoom 40`(핀치·휠), `SHOULDER_OFFSET (1.75, 0.5, 0)` 제거. FOV 65 유지.

### 7.5 남의 부지에서 할 수 있는 것
- 걷기·구경·교문 현판 읽기·전학생 보기(부지 어트리뷰트로 클라이언트가 렌더, 서버 코드 0줄).
- **하늘색 별 줍기**: 각 부지 앞마당의 별 2개는 공용 파트다. 방문객(부지 주인이 아닌 사람)이 밟으면 그 방문객의 스티커판에 +1칸, 서버 `starCooldown[userId][plotId] = os.clock()` 60초, 방문객·부지당 60초에 최대 2개. 밟은 방문객에게만 60초 동안 별이 사라진다(`LocalTransparencyModifier`, 다른 사람에게는 그대로). 주인의 노란 스티커·용돈에는 아무 영향이 없다(주인은 별을 밟아도 반응 없음, 자기 별은 보이지 않음).
  - 근거: "남의 부지 스티커 줍기"가 주는 방문 동기는 살리고, "내 것을 가져간다"는 오해는 오브젝트를 나눠 없앤다. 노란 원판 = 내 것, 하늘색 별 = 놀러 온 사람 것.
- 남의 패드·팻말·접수대·졸업 종·교장 의자는 반응하지 않는다(서버 OwnerId 검사, 클라이언트는 아예 빌보드·프롬프트를 숨김).
- 플레이어끼리는 부딪히지 않는다: PhysicsService 충돌 그룹 「Players」(자기끼리 비충돌), `CharacterAdded` 에서 모든 파트에 지정. 남의 패드 위에 서 있어도 주인의 자동 구매를 막지 못한다(패드 판정은 주인 캐릭터만 센다).
- 점검표(W6·W7 2인 테스트): 방문객이 주인의 진행을 늦출 수 있는 오브젝트 0개 — 패드(주인만) / 스티커(주인만, 방문객은 밟아도 무반응) / 별(방문객만) / 접수대·팻말·졸업 종(주인만) / 교장 의자(주인만) / 문·교문(충돌 없음) / 캐릭터(충돌 없음).
- 좋아요·방문 카운트·트레이딩 없음.

### 7.6 스트리밍
- `default.project.json` Workspace: `StreamingEnabled true`, `StreamingTargetRadius 384`, `StreamingMinRadius 192`, `StreamOutBehavior Opportunistic`, `StreamingIntegrityMode PauseOutsideLoadedArea`(이미 있음), `ModelStreamingBehavior Legacy`. 현재 파일에는 앞의 두 값만 있으므로 나머지를 추가한다.

## 9. 피드백 / juice

### 9.1 공통 규칙
- 모든 행동은 100ms 안에 5~8개 반응(스케일·파티클·소리·숫자 팝·HUD 펀치·햅틱·카메라·플래시 중).
- 카메라 흔들림은 trauma 모델: `shake = trauma²`, 최대 0.6 stud / 1.5°, 감쇠 1.2/s. 구매 0.30, 전설 0.45, 졸업 0.60. 「흔들림 끔」이면 0.
- 이징: 등장 Back Out(overshoot 1.7) 0.18~0.25초, 퇴장 Quad In 0.12초, 숫자 롤 Quad Out 0.4초.
- 서버는 `GameEvent` 를 한 번 보내고(§11.5 페이로드), `FeedbackController` 가 표(이벤트 → 연출 목록)를 읽어 재생한다. 파티클은 `Rate 0 + Emit(n)`, 동시 활성 ≤ 120(졸업식만 ≤ 200).
- 햅틱(`HapticService`, 모바일): 소(스티커) / 중(구매·전학) / 대(전설·졸업). `settings.haptic == false` 면 전부 끔.
- 클라이언트 예측: 스티커는 밟는 순간 클라이언트가 먼저 숨기고 팝을 재생한다. 서버 확인 = 그 스티커 파트의 `Collected` 어트리뷰트가 true 로 바뀌는 것(`GetAttributeChangedSignal`). 0.5초 안에 바뀌지 않으면 다시 보인다. `AncestryChanged` 는 쓰지 않는다.
- 부정 피드백은 없다. 빨강·`denied` 소리·흔들림으로 "안 됨"을 말하지 않는다.

### 9.4 튜토리얼·유도 연출

## 10. NPC 렌더 규칙

### 10.1 원칙
- 전학생 NPC 는 Humanoid 없음. `CharacterBuilder.build` 로 조립한 앵커드 MeshPart 5개(현재 규격 그대로, 감지용 `Head` 센서 파트는 제거) + 소품 ≤ 1 + 등급 표식 ≤ 1(반장 완장·전교1등 메달) = ≤ 7 파트. 서버는 메시를 `preload` 해 `ReplicatedStorage.CharacterPrototypes` 에 두기만 하고 학생 모델을 만들지 않는다.
- 플레이어 아바타는 표준 R15(Game Settings → Avatar 에서 고정), `StarterPlayer.LoadCharacterAppearance true`, 걷기 16 studs/s, 점프 기본. 아바타를 바꾸는 코드는 없다.
- 클라이언트 `StudentRenderController`(신규 작성)가 `ReplicatedStorage.PlotState.PlotNN` 의 어트리뷰트(`Students`, `Facilities`, `Skins`)를 읽어 렌더한다. 자기 부지든 남의 부지든 코드가 같다.
- 시설 모델은 `Workspace.Plots.PlotNN:WaitForChild(facilityId, 5)` 로 기다리고, `ChildAdded`/`ChildRemoved` 로 스트리밍 인·아웃을 따라간다. 모델이 없으면 그 방 학생은 렌더하지 않는다.
- `Seats.seatOf`(§4.3)로 자리를 정하고, 시설 모델의 `Seats/S0n` Attachment 의 CFrame 에 `SIT_HEIGHT 4.8` 기준으로 앉힌다.

### 10.2 애니메이션(모두 클라이언트, CFrame 만)

| 동작 | 규칙 |
|---|---|
| 앉은 idle | 30Hz(`IDLE_RATE 30`), 상체 BOB 0.04 studs · SWAY 0.05 rad, 위상 = 도감 번호 × 0.7(줄이 자로 잰 듯 보이지 않게). 전설은 스케일 1.05 + `ParticleEmitter Rate 2` |
| 손들기 | 8~20초마다 1.5초(`setHandRaised`). 트리거 추가: 플레이어가 8 studs 안에 오면, 도착 직후, 졸업식 2초 |
| 고개 돌리기 | 12 studs 안 플레이어를 향해 ±0.6 rad, 0.3초 |
| 시설별 특수 | 급식실 먹기(팔 1.2초 주기), 음악실 ±4° 몸 흔들기, 도서관 고개 15° 아래 — 3개만. 나머지는 공통 idle |
| 도착 걷기 | 자기 부지에서만, 자기 방 문 → 자리 3.0초 슬라이드 + ±4° 워블(다리 애니메이션 없음) |
| 졸업식 | 강당 좌석 S01~S24 로 순간 이동 후 12초 착석 |

### 10.3 거리 예산
- 렌더 부지 선택: 1초마다 카메라 거리로 부지 12개를 정렬해 가까운 4개만 렌더(교체 이력: 들어올 때 230 studs 안, 나갈 때 260 밖). 저사양(`UserGameSettings.SavedQualityLevel ≤ 3`)은 2개.

| 거리(카메라 → 학생) | 처리 |
|---|---|
| ≤ 60 studs | 매 프레임 갱신 |
| 60~120 | 4프레임마다 |
| > 120 | 정지(마지막 포즈), 렌더 부지 밖이면 모델 파괴(5초 지연) |

- 갱신은 `BulkMoveTo` 한 번에 모아 호출(≤ 300 CFrame/틱). 예산: 동시 렌더 4부지 × 24명 × 5파트 = 480 파트(소품·등급 표식·선생님 포함 ≤ 640), 애니메이션 48명 이하, 학생당 0.3ms 이하.
- `CastShadow false`, `CanCollide false`, `CanQuery false`, `CanTouch false`. 학생당 ≤ 8,000 tri. 텍스처는 변형당 512² 아틀라스(전설 3명 1024²) 19장 ≤ 40MB(`Stats:GetTotalMemoryUsageMb()` 로 W1 측정).
- 선생님 NPC 2명(`TEACHER_F` 교실1 교탁, `TEACHER_M` 교장실 옆) — 장식, 공통 idle 만.

### 10.4 폴백
- `StudentConfig[id].mesh` 가 없거나 프로토타입 로드에 실패하면 `fallbackVariant`(§4.4 표)로 만든다. `CharacterBuilder.preload` 의 "실패 시 error" 는 "실패 시 폴백 등록 + warn" 으로 바꾸고, 클라이언트는 변형별 `WaitForChild(variant, 15)` 실패 시 같은 폴백을 쓴다.

1. 서버 `init.server.luau`: `Remotes.init()`(폴더 `RemoteEvents` 와 이벤트 7개 생성, 가장 먼저) → `DataService.Start` → `task.spawn(StudentService.preloadPrototypes)`(메시 프로토타입, 변형별 실패는 폴백 등록 + warn, 부팅을 막지 않음) → `Geometry` 로 부지 12 + 광장 생성, `ReplicatedStorage.PlotState.Plot01~12` 폴더 생성 → `PlotService.Start`(패드 occupants·스티커·별·Seat·팻말 연결, 부지 CFrame assert) → `EconomyService.Start`(1Hz 틱) → `StudentService.Start` → `MissionService.Start`(60초 틱) → `GraduationService.Start` → `LeaderboardService.Start`(있으면) → `Players.PlayerAdded` 연결 + 이미 접속한 플레이어 처리.

3. 클라이언트: ReplicatedFirst 로딩 화면 → `Remotes.wait()`(`WaitForChild` 30초, 실패 시 warn + 재시도, assert 없음) → `HudController` → `PadController` → `StudentRenderController`(PlotState 12개 구독, `CharacterPrototypes` 변형별 `WaitForChild(variant, 15)` 실패 시 폴백) → `FeedbackController` → `TutorialController` → `CameraController` → `SoundController` → `TransitionController`.

| `FacilityBuilt` | `{ plot: number, facilityId: string }` | 전체(효과음·파티클 트리거만, 모델 등장은 `ChildAdded`) |
| `StudentJoined` | `{ plot: number, studentId: string, walk: boolean }` | 전체(`walk` 는 자기 부지에서만 true) |
| `GachaResult` | `{ studentId, tier, isDupe, dupeCount, boardCells, ticketsLeft, pityLeft, seq }` | 본인 |
| `MissionDone` | `{ index: 1|2|3 }` | 본인 |
| `Graduated` | `{ plot: number, graduations: number, newStudentId: string? }` | 전체 |
| `SkinApplied` | `{ plot: number, facilityId: string, skinIndex: number }` | 전체 |
| `StickerCollected` | `{ stickerId: string, plot: number?, value: number, combo: number, boardCells: number, gold: boolean }` — `plot` 은 별만(별 이름은 부지마다 같다) | 본인 |
| `Deny` | `{ reason: "coins" | "cooldown" | "owner" }` | 본인(연출 없음, 디버그 로그용) |

- 리모트가 아닌 입력(서버 `Touched`/`TouchEnded` + `GetPartBoundsInBox` / `Seat.Occupant` / `ProximityPrompt`): 구매 패드(occupants 집합, 1초마다 재확인, EconomyService 틱이 「주인이 위에 있고 coins ≥ price」면 구매), 스티커, 하늘색 별, 교장 의자, 입학 접수대(패널 열기만, 클라이언트), 「우리 학교로」 팻말. 공통 검증: 발화 파트의 부지 `OwnerId == player.UserId`(별·팻말은 반대), `HumanoidRootPart` 와 파트 거리 ≤ 12 studs, 파트별 디바운스 0.3초.
- 스티커 치트 상한: 플레이어당 줍기 토큰 버킷(≥0.4초 간격), `lastPickupPos/Time` 로 계산한 이동 속도 > 40 studs/s 면 무시 + 위반 기록. `Collected` 어트리뷰트 → `CanTouch false` → 15초 뒤 재활성(`Gold` 어트리뷰트 갱신).
- `RemoteGuard`(모듈): 플레이어당 토큰 버킷 10/s, 문자열 길이 > 32 무시, `NaN`/`inf` 무시, 타입 검사. 위반 20회/10분 → 로그 + `Kick("다시 들어와 주세요")`.
- 클라이언트가 값(가격·수입·확률)을 보내는 리모트는 없다. 클라이언트는 무엇을 살지 고를 수 없다(패드가 정한다).

### 11.6 ProfileStore 스키마(`Types.Profile`, 약 1KB)
```lua
local SCHEMA_VERSION = 1

local TEMPLATE = {
	version = SCHEMA_VERSION,
	coins = 10,
	tickets = 0,
	stickerBoard = 0,        -- 0..59
	graduations = 0,
	facilities = {},         -- { desk = true, ... }  (문자열 키)
	skinsOwned = {},         -- { ["desk:2"] = true }
	skinsApplied = {},       -- { desk = 2 }  (졸업해도 유지)
	students = {},           -- { s14 = 1, s17 = 3 }  값 = 보유 횟수(중복 포함)
	pity = 0,                -- 전설 없이 뽑은 장수
	missions = { day = 0, stickers = 0, built = 0, chair = false, done = { false, false, false } },
	settings = { shake = true, sfx = true, haptic = true },
	stats = { totalCoins = 0, totalStickers = 0, totalPulls = 0, playSeconds = 0 },
}

-- MIGRATIONS[v] 는 version v 의 데이터를 v+1 로 올린다. 필드 추가는 Reconcile 이 처리하므로 항목이 없다.
local MIGRATIONS: { [number]: (data: any) -> () } = {}

-- 로드 직후(DataService.load):
profile:Reconcile()
while profile.Data.version < SCHEMA_VERSION do
	MIGRATIONS[profile.Data.version](profile.Data)
	profile.Data.version += 1
end
```
- 콤보는 프로필에 없다(서버 세션 표). 튜토리얼 상태도 없다(파생).
- 스키마 규칙: 필드 추가 = TEMPLATE 만 고친다(Reconcile). 이름 변경·삭제·의미 변경 = `SCHEMA_VERSION + 1` 과 `MIGRATIONS[이전]` 항목. 현재 실제 `DataService.luau` 에는 이 루프가 없으므로 W1 에 추가한다.
- 저장 시점: 명시 저장 3곳 — 졸업(§6.1), 미션 완료, 퇴장(`EndSession`). 구매·뽑기는 `DataService.saveDebounced(player, 30)`(마지막 호출 30초 뒤 1회). 그 밖은 ProfileStore 자동 저장 300초. 손실 상한 30초(디바운스가 실패해도 최악 5분).
- Studio 는 기존 규칙 그대로 `PrincipalProfile_Dev` + Mock, `UseLiveDataStore` 어트리뷰트로 실 DataStore 검증. `profile:AddUserId(player.UserId)` 는 기존 코드 그대로.

### 12.2 어린이 안전
- 채팅은 `TextChatService` 기본(로블록스 필터). 음성 채팅 끔. 게임 안에 자유 텍스트 입력이 없다. 학교 이름 = `DisplayName .. "의 학교"`. 리더보드·현판 어디에도 Username 을 쓰지 않으며, DisplayName 조회 실패 시 「교장 #끝4자리」.
- 뽑기: 확률 점판이 패널 안에 항상 펼쳐져 있다(접힘·툴팁 없음). 레버·릴·코인 투입구·잭팟 불빛·카지노 소리·니어미스 없음(§5.4). 원서를 Robux 나 다른 유료 재화로 사는 경로는 설계상 없다 — 만약 언젠가 넣으려면 `PolicyService.GetPolicyInfoForPlayerAsync().ArePaidRandomItemsRestricted` 로 숨기고 확률 표시 법규 검토가 먼저다. 현재는 이 값을 로그만 한다.
- Robux 결제·광고·트레이딩·외부 링크·설문·연령 게이트 없음.
- 깜빡임 제한(§8.4). 카운트다운 타이머 없음. 오프라인 수입·출석 보상·서버 이벤트 없음. 부정 피드백(빨강·`denied`·흔들림) 없음.
- 개인정보: UserId 만 저장. ProfileStore `profile:AddUserId(player.UserId)`(GDPR 삭제 대응, 기존 코드). 리더보드 `OrderedDataStore` 는 수동 `RemoveAsync` 절차.
- 킥 문구(≤ 12자)는 「다시 들어와 주세요」 하나다: 프로필 로드 실패·세션 잠금 충돌·RemoteGuard 위반. 저장 실패로는 킥하지 않는다(경고 로그 + 1회 재시도, 이후 ProfileStore 자동 저장이 다시 시도).
- 치트 상한: 서버가 모든 수치를 계산하므로 클라이언트 조작으로 얻을 수 있는 이득은 0. 리모트 위조는 `RemoteGuard` 가 무시, 20회/10분이면 킥. 스티커·별은 속도·간격·쿨다운 상한(§11.5).
- Creator Dashboard Experience Guidelines 설문(W8 게이트, 목표 등급 전체(Minimal)):

| 설문 항목 | 답 | 근거 |
|---|---|---|
| 유료 무작위 아이템 | 없음 | 원서는 게임 내 재화만, Robux 경로 없음 |
| 무료 무작위 아이템 | 있음 — 확률 상시 표시, 항상 무언가를 획득(중복도 판 칸) | §5.4 |

| 폭력·공포·피 | 없음 | 학교 타이쿤, 적 없음 |

### 13.2 6주 컷(최소 출시본)
- 포함: 1~6주 전부(리더보드는 코드만, 광장 파트 미배치). 제외: 리더보드 노출, 아이 테스트(개발자 가족 1명으로 대체), 신규 메시 미완분(폴백 유지), 시설별 특수 애니메이션 3종, 방문객 별.
- 순서 불변: 코어 루프(2주) → 학생(3주) → 졸업·튜토리얼(4주). W1~W4 가 밀리면 5·6주 항목을 자르지, 이 순서를 바꾸지 않는다. W5~W6 에는 자를 수 있는 것(juice·리더보드·별·특수 애니)만 두고 출시 필수 항목(안전 점검·성능 측정·2인 테스트)은 W6 앞쪽에 고정한다.
- 삭감 우선순위: ① 방문객 별 ② 시설별 특수 애니메이션 ③ 스킨 D(졸업 1회+) 14종 → 출시 후 ④ 콤보 연출(판정은 유지) ⑤ 튜토리얼 에스컬레이션 60초 카메라 팬 단계(30초 화살표는 유지).

## 부록 C. 시뮬레이션 사용법
- `python3 sim-final.py > sim-final-output.md` — 1회차 표(10~90% 포함)·분 단위 곡선·방치형·뽑기 기여 0 하한·2회차 A/B 모드 표·3회차 표·12회차 궤적(2,000명)·학생별 획득 회차·확률 실측.
- `python3 sim-final.py --tune` — 확률·천장 변형 4종 비교(§5.4 근거). 회수율 40/55/70% 민감도(§5.2)는 기본 실행 출력에 있다.
- 상수 블록은 `src/shared/Config/EconomyConfig.luau`, `FacilityConfig.luau`(순서·가격·수입), `GachaConfig.luau`, `StudentConfig.luau`(해금 회차·기여·id s01~s24) 와 이름·값이 같아야 한다. W8 튜닝은 §5.7 다이얼만 만진다. 시뮬은 원서를 얻는 즉시 뽑고 기여를 즉시 반영하므로 실제 게임의 첫 1분(1:05 첫 뽑기)은 §2.2 시각이 우선한다.
- `python3 check-config.py` — 시뮬 상수와 `src/shared/Config`(Economy·Facility·Student·Gacha)를 한 줄씩 대조해 표로 찍는다. 하나라도 다르면 종료 코드 1(§13.1 W8 게이트, 다이얼을 돌린 뒤 매번).
