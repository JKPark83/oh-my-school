## 1. 한 줄 컨셉 + 30초/5분/30분 루프

**한 줄 컨셉**: 빈 교실 하나를 물려받은 꼬마 교장이 칭찬스티커를 주워 학교 한 동을 짓고, 전학생 24명을 모아 졸업식을 열고, 다음 회차에 더 큰 학교를 다시 짓는 한국 초등학교 타이쿤.

**핵심 규칙 한 가지(7세가 배우는 유일한 규칙)**: 구매 패드 위에 서 있으면 링이 차는 순간 시설 부품이 하나 솟는다(시설마다 3~4개). 링이 이미 찼으면 밟는 순간. 마지막 부품으로 시설이 완공되면 전학생이 그 방 문으로 걸어 들어와 앉는다.

**수입 공식**: 초당 수입 = Σ(지은 시설 초당 수입) × (1 + Σ재학생 기여) × (1 + 1.0 × 졸업 횟수)

**재화 1종 + 선물판**: 용돈(코인, 시설 구매). 스티커를 주우면 선물판이 한 칸씩 차고, 40칸이 차면 선물이 하나 열린다(순번 1·2·3·5·8·12 는 꾸미기 소품, 나머지는 용돈, §5.4·§5.8).

- 강당·체육관·운동장 3개는 신규 메시 없이 파트만으로 만든다. `generate_mesh` 는 전학생 8명에만 쓴다.

- `Seats.seatOf(studentId, builtFacilities) → { facilityId, index } | nil`: 그 학생의 시설이 지어져 있으면 자리, 아니면 nil. nil 인 학생은 "등교 전"으로 렌더하지 않는다(수입 배율에는 항상 전원 반영).
- 시설이 서는 순간 그 방에 자리가 있는 보유 학생 전원이 그 방 문으로 걸어 들어온다(자기 부지: 걷기, 남의 부지·재접속: 페이드 인). 졸업 뒤 다시 지을 때도 같은 코드가 "돌아오는" 연출을 만든다.
- 시설별 자리 요약: 교실1 S01~S06 = s01 s02 s03 s04 s14 s17 / 교실2 S01~S06 = s22 s05 s18 s15 s16 s23 / 급식실 S01~S04 = s06 s19 s20 s21 / 도서관 S01~S03 = s07 s24 s25 / 보건실 S01 = s08 / 과학실 S01~S02 = s09 s11 / 음악실 S01~S02 = s10 s12 / 교장실 S01 = s13.

### 5.3 칭찬스티커 기여
- 스티커 가치 = max(10 × 1.35^N, 초당 수입 × 1.2초). 1회차 처음 1분은 10원(스티커 1개 = 책상 부품 1개값), 그 뒤로는 항상 "수입 1.2초어치" → 줍기의 상대 가치가 회차·시설과 무관하게 일정하다.
- 스티커를 안 주우면(튜토리얼 3장만) 1회차가 6분 늘어난다(17:18 → 23:24). 줍기는 "필수는 아니지만 확실히 빠른" 선택.
- 스티커 1개는 선물판 +1칸이다(황금도 +1칸, 5콤보마다 +1칸, §5.4).
- 황금 스티커: 서버가 `(stats.totalStickers + 1) % 12 == 0` 이면 다음에 리스폰하는 스티커에 `Gold = true` 어트리뷰트를 붙인다(그래서 미리 금색으로 보인다). 가치 ×5. 기대값을 4/3배로 올리고 분산을 준다.
- 스티커 파트는 서버가 `Collected` 어트리뷰트를 먼저 세팅하고 `CanTouch = false` 로 끈 뒤 15초 후 재활성한다. 클라이언트 예측의 확인 채널은 이 어트리뷰트다(§9.1).

**놓기·옮기기 판정 ①~⑧(서버 `DecorService`, 클라도 같은 `DecorGrid.canPlace` 로 먼저 판정)**: ① RemoteGuard 통과 ② 자기 부지 ③ 아이템 id 가 DecorConfig 에 있음 ④ 보관함에 1개 이상(놓기) ⑤ cx·cz 가 0..29 정수이고 w×d 가 부지 안 ⑤' f 가 1 또는 3..2+층 수 정수 ⑥ 회전 0..3 정수 ⑦ 막힌 칸·다른 꾸미기와 겹침 없음(옮기기는 자기 자리를 빼고 본다) ⑧ 놓인 수 < MAX_PLACED 40. 통과하면 보관함 −1, 배치 목록에 더한다. 거부 reason: ③④ → `owned`, ⑤⑤'⑦ → `cell`, ⑧ → `limit`.

**사기·돌려주기 판정 ⑴~⑸(`BuyDecor`·`ReturnDecor`)**: ⑴ RemoteGuard 통과 ⑵ 아이템 id 가 DecorConfig 에 있음 ⑶ 상점에 진열됨(아니면 `locked`) ⑷ 코인 ≥ `priceOf`(아니면 `coins`) ⑸ 보관함 + 배치 < MAX_OWNED 10(아니면 `owned`). 통과하면 코인을 빼고 보관함 +1(`stats.totalCoins` 는 그대로). 친구 아이템이면 그 학생이 없을 때만 바로 전학 온다(`StudentService.grant`, 걸어 들어옴). 돌려주기는 보관함에 있는 것만(아니면 `owned`) 받고 산 값을 그대로 돌려준다(`decorPaid[item]` 스택의 맨 뒤 값). 튜토리얼 화분·선물 소품·DevCheat 처럼 무료로 받은 것은 스택에 없어 0 이다. 졸업 뒤 가격이 올라도 환불은 산 값이라 졸업 전에 사 두었다 되파는 차익이 없다. 돌려줘도 친구 학생은 남는다. 클라는 무엇을 살지만 보내고 값은 보내지 않는다.

- 거부는 `GameEvent{kind = Deny}` 로만 알린다. 클라가 먼저 판정하므로 서버 거부는 어긋난 경우뿐이고, 위반 카운트는 올리지 않는다(§11.5).
- 실패했을 때 아이가 보는 것(주인 화면만): 놓을 수 없는 칸이면 고스트가 회색 반투명, ✓ 가 흐려진다. 막는 꾸미기·패드는 노란 윤곽선이 1Hz 이하로 천천히 반짝인다. 40개가 차면 40칸 막대가 천천히 반짝인다. 흐린 ✓ 를 누르면 짧은 `nudge` 소리와 함께 고스트가 가장 가까운 놓을 수 있는 칸(맨해튼 거리 ≤ 6)으로 0.2초 동안 옮겨 간다. 서버가 거부하면 고스트가 0.2초 페이드로 보관함에 돌아간다. 빨강·흔들림은 없다(§12.2).
- 튜토리얼: 새 프로필 보관함에 화분 2개(`TUTORIAL_ITEM`·`TUTORIAL_FREE`)가 있다. `DataService.load` 가 `decorStarter` 플래그로 한 번만 넣고, 산 값이 없으니 돌려줘도 0 이다.
- 충돌 없음: 꾸미기 파트는 클라이언트가 그리고 `CanCollide`·`CanTouch` 가 false 다(서버 파트 0). 캐릭터가 선 칸에 놓아도 걸어 나갈 수 있고 스티커·패드 판정이 바뀌지 않는다.

### 8.4 접근성
- 「흔들림 끔」: 카메라 흔들림·FOV 펀치·화면 플래시·히트스톱을 모두 끈다(파티클·소리는 유지). 프로필 `settings.shake`.
- 「진동 끔」: 햅틱 전부 끔. 프로필 `settings.haptic`. 「음소거」: `settings.sfx`.
- 등급은 색 + 테두리 두께(2/3/4/6px) + 등급 글자 3중 표기.
- 깜빡임: 플래시 α ≤ 0.7, 지속 ≤ 0.08초, 1초에 1회 이하.

## 9. 피드백 / juice

### 9.1 공통 규칙
- 모든 행동은 100ms 안에 5~8개 반응(스케일·파티클·소리·숫자 팝·HUD 펀치·햅틱·카메라·플래시 중).
- 카메라 흔들림은 trauma 모델: `shake = trauma²`, 최대 0.6 stud / 1.5°, 감쇠 1.2/s. 구매 0.30, 졸업 0.60. 「흔들림 끔」이면 0.
- 이징: 등장 Back Out(overshoot 1.7) 0.18~0.25초, 퇴장 Quad In 0.12초, 숫자 롤 Quad Out 0.4초.
- 서버는 `GameEvent` 를 한 번 보내고(§11.5 페이로드), `FeedbackController` 가 표(이벤트 → 연출 목록)를 읽어 재생한다. 파티클은 `Rate 0 + Emit(n)`, 동시 활성 ≤ 120(졸업식만 ≤ 200).
- 햅틱(`HapticService`, 모바일): 소(스티커) / 중(구매·전학) / 대(전설·졸업). `settings.haptic == false` 면 전부 끔.
- 클라이언트 예측: 스티커는 밟는 순간 클라이언트가 먼저 숨기고 팝을 재생한다. 서버 확인 = 그 스티커 파트의 `Collected` 어트리뷰트가 true 로 바뀌는 것(`GetAttributeChangedSignal`). 0.5초 안에 바뀌지 않으면 다시 보인다. `AncestryChanged` 는 쓰지 않는다.
- 부정 피드백은 없다. 빨강·`denied` 소리·흔들림으로 "안 됨"을 말하지 않는다.

## 10. NPC 렌더 규칙

### 10.1 원칙
- 전학생 NPC 는 Humanoid 없음. `CharacterBuilder.build` 로 조립한 앵커드 MeshPart 5개(현재 규격 그대로, 감지용 `Head` 센서 파트는 제거) + 소품 ≤ 1 + 등급 표식 ≤ 1(반장 완장·전교1등 메달) = ≤ 7 파트. 서버는 메시를 `preload` 해 `ReplicatedStorage.CharacterPrototypes` 에 두기만 하고 학생 모델을 만들지 않는다.
- 플레이어 아바타는 표준 R15(Game Settings → Avatar 에서 고정), `StarterPlayer.LoadCharacterAppearance true`, 걷기 16 studs/s, 점프 기본. 아바타를 바꾸는 코드는 없다.
- 클라이언트 `StudentRenderController`(신규 작성)가 `ReplicatedStorage.PlotState.PlotNN` 의 어트리뷰트(`Students`, `Facilities`)를 읽어 렌더한다. 자기 부지든 남의 부지든 코드가 같다.
- 시설 모델은 `Workspace.Plots.PlotNN:WaitForChild(facilityId, 5)` 로 기다리고, `ChildAdded`/`ChildRemoved` 로 스트리밍 인·아웃을 따라간다. 모델이 없으면 그 방 학생은 렌더하지 않는다.
- `Seats.seatOf`(§4.3)로 자리를 정하고, 시설 모델의 `Seats/S0n` Attachment 의 CFrame 에 `SIT_HEIGHT 4.8` 기준으로 앉힌다.

### 10.2 애니메이션(모두 클라이언트, CFrame 만)

| 동작 | 규칙 |
|---|---|
| 앉은 idle | 30Hz(`IDLE_RATE 30`), 상체 BOB 0.04 studs · SWAY 0.05 rad, 위상 = 도감 번호 × 0.7(줄이 자로 잰 듯 보이지 않게). 전설은 스케일 1.05 + `ParticleEmitter Rate 2` |
| 손들기 | 8~20초마다 1.5초(`setHandRaised`). 트리거 추가: 플레이어가 8 studs 안에 오면, 도착 직후, 졸업식 2초 |
| 고개 돌리기 | 12 studs 안 플레이어를 향해 ±0.6 rad, 0.3초 |
| 시설별 특수 | 급식실 먹기(팔 1.2초 주기), 음악실 ±4° 몸 흔들기, 도서관 고개 15° 아래 — 3개만. 나머지는 공통 idle |
| 도착 걷기 | 자기 부지에서만, 자기 방 문 → 자리 3.0초 슬라이드 + ±4° 워블(다리 애니메이션 없음) |
| 졸업식 | 강당 좌석 S01~S24 로 순간 이동 후 12초 착석 |

### 10.3 거리 예산
- 렌더 부지 선택: 1초마다 카메라 거리로 부지 12개를 정렬해 가까운 4개만 렌더(교체 이력: 들어올 때 230 studs 안, 나갈 때 260 밖). 저사양(`UserGameSettings.SavedQualityLevel ≤ 3` 이거나 10초 평균 FPS < 30, 한 번 켜면 끄지 않음)은 2개.

| 거리(카메라 → 학생) | 처리 |
|---|---|
| ≤ 60 studs | 매 프레임 갱신 |
| 60~120 | 4프레임마다 |
| > 120 | 정지(마지막 포즈), 렌더 부지 밖이면 모델 파괴(5초 지연) |

- 갱신은 `BulkMoveTo` 한 번에 모아 호출(≤ 300 CFrame/틱). 예산: 동시 렌더 4부지 × 24명 × 5파트 = 480 파트(소품·등급 표식·선생님 포함 ≤ 640), 애니메이션 48명 이하, 학생당 0.3ms 이하.
- `CastShadow false`, `CanCollide false`, `CanQuery false`, `CanTouch false`. 학생당 ≤ 8,000 tri. 텍스처는 변형당 512² 아틀라스(전설 3명 1024²) 19장 ≤ 40MB(`Stats:GetTotalMemoryUsageMb()` 로 W1 측정).
- 선생님 NPC 2명(`TEACHER_F` 교실1 교탁, `TEACHER_M` 교장실 옆) — 장식, 공통 idle 만.

### 10.4 폴백
- `StudentConfig[id].mesh` 가 없거나 프로토타입 로드에 실패하면 `fallbackVariant`(§4.4 표)로 만든다. `CharacterBuilder.preload` 의 "실패 시 error" 는 "실패 시 폴백 등록 + warn" 으로 바꾸고, 클라이언트는 변형별 `WaitForChild(variant, 15)` 실패 시 같은 폴백을 쓴다.

| `DecorStored` | `{ slot: number, item: string }` | 본인 |
| `DecorBought` | `{ item: string, coins: number, student: string? }` — `coins` = 뺀 값, `student` = 이번에 전학 온 친구 | 본인 |
| `DecorReturned` | `{ item: string, coins: number }` — `coins` = 돌려준 값 | 본인 |
| `Deny` | `{ reason: "coins" | "cooldown" | "owner" | "cell" | "limit" | "owned" | "locked" }` | 본인(꾸미기 거부는 고스트를 보관함으로 되돌림, 그 밖은 연출 없음·디버그 로그용) |

- 리모트가 아닌 입력(서버 `Touched`/`TouchEnded` + `GetPartBoundsInBox` / `Seat.Occupant` / `ProximityPrompt`): 구매 패드(occupants 집합, 1초마다 재확인, EconomyService 틱이 「주인이 위에 있고 coins ≥ 다음 부품 가격」이면 부품 1개 구매, 틱당 1개), 스티커, 하늘색 별, 교장 의자, 「우리 학교로」 팻말(입학 접수대 입력은 W4 에 없앴다). 공통 검증: 발화 파트의 부지 `OwnerId == player.UserId`(별·팻말은 반대), `HumanoidRootPart` 와 파트 거리 ≤ 12 studs, 파트별 디바운스 0.3초.
- 스티커 치트 상한: 플레이어당 줍기 토큰 버킷(≥0.4초 간격), `lastPickupPos/Time` 로 계산한 이동 속도 > 40 studs/s 면 무시 + 위반 기록. `Collected` 어트리뷰트 → `CanTouch false` → 15초 뒤 재활성(`Gold` 어트리뷰트 갱신).
- `RemoteGuard`(모듈): 플레이어당 토큰 버킷 10/s, 문자열 길이 > 32 무시, `NaN`/`inf` 무시, 타입 검사. 위반 20회/10분 → 로그 + `Kick("다시 들어와 주세요")`.
- 꾸미기 리모트 5개는 핸들러 판정에서 거부하면 조용히 무시하는 대신 `Remotes.deny` 로 알리고, 위반 카운트는 올리지 않는다(클라가 같은 `DecorGrid` 로 먼저 막으므로 어긋난 경우뿐이다). 인자 타입·속도 위반은 다른 리모트와 같이 `RemoteGuard` 가 조용히 무시하고 센다.
- 클라이언트가 값(가격·수입)을 보내는 리모트는 없다. 시설 부품은 무엇을 살지 고를 수 없고(패드가 정한다), 꾸미기는 무엇을 살지만 고르며 값은 서버가 `DecorConfig.priceOf` 로 계산한다.

### 11.6 ProfileStore 스키마(`Types.Profile`, 약 1KB)
```lua
local SCHEMA_VERSION = 2

local TEMPLATE = {
	version = SCHEMA_VERSION,
	coins = 10,
	stickerBoard = 0,        -- 선물판 칸 0..39(40 이 되면 GiftBoard.settleBoard 가 바로 선물로 바꾼다)
	giftIndex = 0,           -- 지금까지 받은 선물 수. 다음 선물 = 순서표의 giftIndex+1 번째
	graduations = 0,
	facilities = {},         -- { desk = true, ... }  (문자열 키, 완공 시설만)
	buildParts = 0,          -- 다음 시설에서 이미 산 부품 수(0..부품 수-1). 완공·졸업 때 0
	students = {},           -- { s01 = 1, s18 = 1 }  보유 학생(값은 1)
	missions = { day = 0, stickers = 0, built = 0, chair = false, done = { false, false, false } },
	settings = { shake = true, sfx = true, haptic = true },
	stats = { totalCoins = 0, totalStickers = 0, playSeconds = 0 },
	decorOwned = {},         -- { [item] = 개수 } 보관함. 0 이면 키 없음(중첩 기본값을 두면 Reconcile 이 지운 키를 다시 채운다)
	decorPlaced = {},        -- { DecorPlacement }  DecorPlacement = { item, cx, cz, rot, f? }(f 없으면 1층)  배열 순서 = slot
	decorPaid = {},          -- { [item] = { 산 값, ... } } 돌려주기용 스택. 비면 키 없음. ProfileSync 에는 싣지 않는다
	decorStarter = false,    -- load 가 false 면 보관함에 화분 2개(TUTORIAL_ITEM·TUTORIAL_FREE)를 넣고 true 로 바꾼다
	towerFloors = 0,         -- 산 층 수. W6 부터 채움
}

-- MIGRATIONS[v] 는 version v 의 데이터를 v+1 로 올린다(src/server/Migrations.luau). 필드 추가는 Reconcile 이 처리한다.
local MIGRATIONS: { [number]: (data: any) -> () } = Migrations

-- 로드 직후(DataService.load):
profile:Reconcile()
while profile.Data.version < SCHEMA_VERSION do
	MIGRATIONS[profile.Data.version](profile.Data)
	profile.Data.version += 1
end
```
- v1 → v2(W4, `Migrations[1]`): `tickets`·`pity`·`stats.totalPulls` 를 지운다. `students` 는 다시 계산한다 — s01~s13 은 그 시설이 완공이거나 졸업 ≥1 이면, s18 은 졸업 ≥1, s23 은 졸업 ≥5 일 때만 남기고 s14~s24 의 나머지는 지운다(개선계획 §7 질문 6). `stickerBoard` 는 그대로 두므로 옛 판이 40칸 이상이면 다음 스티커 때 선물로 바뀐다. 새 필드는 Reconcile 이 채우고, `Migrations[1]` 도 `decorOwned` 가 없으면 TEMPLATE 과 같은 `{}` 로 채운다(스키마는 v2 그대로). 튜토리얼 화분은 migrate 뒤 `decorStarter` 가 false 일 때 한 번만 넣는다(새 프로필·옛 프로필 같음).
- 콤보는 프로필에 없다(서버 세션 표). 튜토리얼 상태도 없다(파생).
- 스키마 규칙: 필드 추가 = TEMPLATE 만 고친다(Reconcile). 이름 변경·삭제·의미 변경 = `SCHEMA_VERSION + 1` 과 `MIGRATIONS[이전]` 항목. 루프는 `DataService.luau`, 변환표는 `src/server/Migrations.luau` 에 있다. 예외: 2026-09-29 스킨 폐기로 `skinsOwned`·`skinsApplied` 를 TEMPLATE 에서 지웠지만 실 데이터가 없어 버전을 올리지 않았다(남은 키는 Reconcile 이 두므로 무해).
- 저장 시점: 명시 저장 3곳 — 졸업(§6.1), 미션 완료, 퇴장(`EndSession`). 구매·스티커·꾸미기는 `DataService.saveDebounced(player, 30)`(마지막 호출 30초 뒤 1회). 그 밖은 ProfileStore 자동 저장 300초. 손실 상한 30초(디바운스가 실패해도 최악 5분).
- Studio 는 기존 규칙 그대로 `PrincipalProfile_Dev` + Mock, `UseLiveDataStore` 어트리뷰트로 실 DataStore 검증. `profile:AddUserId(player.UserId)` 는 기존 코드 그대로.

### 12.2 어린이 안전
- 채팅은 `TextChatService` 기본(로블록스 필터). 음성 채팅 끔. 게임 안에 자유 텍스트 입력이 없다. 학교 이름 = `DisplayName .. "의 학교"`. 리더보드·현판 어디에도 Username 을 쓰지 않으며, DisplayName 조회 실패 시 「교장 #끝4자리」.
- 선물판: 선물 순서가 고정이라 무작위·확률 보상이 없다(§5.4). 레버·릴·코인 투입구·잭팟 불빛·카지노 소리·니어미스 없음. 게임 재화를 Robux 로 사는 경로는 설계상 없다 — 만약 언젠가 유료 무작위 아이템을 넣으려면 `PolicyService.GetPolicyInfoForPlayerAsync().ArePaidRandomItemsRestricted` 로 숨기고 확률 표시 법규 검토가 먼저다. 현재는 이 값을 로그만 한다.
- Robux 결제·광고·트레이딩·외부 링크·설문·연령 게이트 없음.
- 깜빡임 제한(§8.4). 카운트다운 타이머 없음. 오프라인 수입·출석 보상·서버 이벤트 없음. 부정 피드백(빨강·`denied`·흔들림) 없음.
- 개인정보: UserId 만 저장. ProfileStore `profile:AddUserId(player.UserId)`(GDPR 삭제 대응, 기존 코드). 리더보드 `OrderedDataStore` 는 수동 `RemoveAsync` 절차.
- 킥 문구(≤ 12자)는 「다시 들어와 주세요」 하나다: 프로필 로드 실패·세션 잠금 충돌·RemoteGuard 위반·빈 부지 없음(나간 사람의 부지가 풀리기 전에 13번째로 들어온 경우). 저장 실패로는 킥하지 않는다(ProfileStore 자동 저장이 다시 시도한다).
- 치트 상한: 서버가 모든 수치를 계산하므로 클라이언트 조작으로 얻을 수 있는 이득은 0. 리모트 위조는 `RemoteGuard` 가 무시, 20회/10분이면 킥. 스티커·별은 속도·간격·쿨다운 상한(§11.5).
